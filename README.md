# DUO Killer · iPhone DUO 抢购辅助与 Apple 商城快速下单

面向 **iPhone DUO 抢购准备与快速下单** 的 Apple 中国在线商店辅助工具，支持 **macOS、Windows 和本地 Web**。提前配置账号、商品 SKU、购买数量和收货地址，在同一个界面完成登录检查、加入购物袋、结账确认、生成付款二维码和订单查询。

iPhone DUO launch assistant and Apple Store quick checkout tool for macOS, Windows and local Web. Built with Tauri, Rust, React and Python.

本仓库基于 [Jasper-zzq/iPhoneDuo](https://github.com/Jasper-zzq/iPhoneDuo) 的本地修改版本，包含结算提速、失败状态核对恢复及订单取消。按本次所选商品和数量自动结算，无独立商品授权白名单、固定数量或金额上限；不附加 AppleCare+。地址按账号独立保存，价格、库存和实际限购数量以官网返回为准。旧 `automation.json` 不再作为下单条件。

## 主要功能

| 功能 | 说明 |
| --- | --- |
| iPhone DUO 发售状态与库存监控 | 无需 Apple 登录读取发售提示；可从接口选多家门店，每秒监控实际库存并联动自提抢购。未知状态不代表有货。 |
| 商品与数量预设 | 内置 Duo 白色 256GB、512GB、iPhone 18 Pro 银色 256GB 与抛光布 SKU，默认数量为 1。 |
| 快速下单 | 自动送货并使用本地地址和联系方式；核对商品、数量、地址、金额与支付宝后创建订单。 |
| 临时失败恢复 | 送货、地址、支付方式失败后先读取当前结算状态，已完成则继续，仍在原步骤且允许继续时有限重试。 |
| 重复下单 | 加购与最终下单请求不自动重发；人工再次下单仍由 Apple 判断是否接受。自动队列遇到未知提交时停止该账号后续派发，先核对官网结果。 |
| 多账号独立运行 | 每个账号独立保存会话、设备信任和浏览器配置；不同账号可以并行操作，验证码与确认提示标明所属账号。 |
| 登录与设备信任 | 支持设备验证码、短信验证码及官网浏览器登录，保存并复用当前账号有效的设备信任；需要重新认证时按提示完成登录。 |
| 配送与门店自提 | 可使用官网已有地址或本地快捷地址，支持选择官网返回的可取货门店。 |
| 支付与订单查询 | 确认下单后立即展示订单信息，随后加载支付宝二维码；支持查询及取消官网允许取消的未付款订单。 |
| 手机 PWA 与后台通知 | 默认密码保护的 HTTPS Quick Tunnel；库存变化通知及每分钟待付款提醒，最长 30 分钟。 |
| 并发自提 | 默认 1 路，可配 1–10 路；下单失败支持配置 0–10 次额外串行重试，已有订单或提交未知即停止。 |
| 自动执行队列 | 监控有货目标按 FIFO 保存，默认逐个执行，也可固定并发；账号忙时保留排队，队列共用 10 个下单子路名额。 |
| 运行日志与会话恢复 | 按账号、任务、类别查看结构化日志；保留原账号和浏览器资料恢复官网会话，PWA 可操作当前任务的官方浏览器窗口。 |

**DUO 使用流程：**提前配置账号与地址、预热登录 → 刷新发售状态 → 选择商品 → 立即下单 → 自动核对并创建订单 → 扫码支付 → 查询订单。

发售提示可手动刷新，实际库存可持续监控；库存、价格和是否可购买以 Apple 实际返回为准，付款由本人扫码完成。

**手机远程入口：**安装官方 `cloudflared` 后运行 `pnpm pwa` 或双击 `start-pwa.cmd`，启动器保留已有 Web 账号数据并显示 HTTPS 地址与默认密码。手机添加到主屏幕后启用通知。参见 [自动监控、并发自提与 PWA](docs/MONITOR-PWA.md)。

**队列与账号会话：**队列按最新倒序显示、实际保持 FIFO；无货或关闭授权后保留未执行任务，手动取消仍有效。账号下单空闲 10 分钟后执行“预热登录（不加购）”，手动、定时和监控下单优先。通知、密码及安装入口统一放在“应用设置”，自动监控提供最近有货事件列表。使用流程、持久化 ACK 和恢复边界见 [执行队列、结构化日志与官网会话恢复](docs/QUEUE-LOGS-SESSION.md)。

**统一界面与手机操作：**全局下拉使用同一组件，数量、并发和重试使用可输入的加减步进器；手机触摸区域至少 44px。最近有货按“时间、型号、门店”列表展示，队列和日志减少嵌套卡片，商品及订单表格适配窄屏。设计与截图审查、验证范围见 [界面统一与手机适配](docs/UI-CONSISTENCY-REVIEW.md)。

**下单进度与紧凑列表：**顶部固定显示当前下单步骤，可切换账号任务并前往处理；待付款和提交未知分别突出提醒。执行队列优先展示商品、当前步骤及失败原因；运行日志按毫秒时间、彩色级别和单行内容扫读，点按展开完整信息。展开器统一为 SVG 箭头，监控设置展开时保持标题和操作位置稳定。详见 [下单进度、日志与展开交互](docs/INTERACTION-REFINEMENT.md)。

## 快速启动（Web）

**使用源码：**准备 Node.js 22.22+、pnpm 11.9、Rust stable、Python 3.10+（建议 3.12）。macOS 需 Xcode Command Line Tools，Windows 需 MSVC C++ Build Tools。具体安装见 [Tauri 前置要求](https://v2.tauri.app/zh-cn/start/prerequisites/)。

克隆仓库后启动：

```sh
git clone https://github.com/fantasy194/applestore_shot.git
cd applestore_shot
pnpm install --frozen-lockfile
pnpm dev:web
```

程序自动准备 Python 环境、编译本地服务并打开浏览器。在启动终端按 **Ctrl+C** 退出服务；仅关闭网页不会退出服务。

**使用构建好的 Web 版：**macOS 双击 `local-web-release/启动.command`，Windows 双击 `local-web-release/start.cmd`。保留整个目录，无需安装开发环境。

**Docker Compose：**在项目目录执行 `docker compose up -d --build --wait`，打开 `http://127.0.0.1:17654`，从 `docker compose logs app` 获取首次访问密码。镜像支持 `linux/amd64` 和 `linux/arm64`，分别内置 GUI Google Chrome 和 Chromium，以及虚拟显示器；账号和浏览器资料保存在独立数据卷。GitHub Actions 在推送 `main` 或 `v*` 标签时构建、验证两种架构，并发布到 `ghcr.io/fantasy194/applestore_shot`。直接拉取镜像、详细配置和数据保留说明见 [Docker 本地部署](docker/README.md)。

**树莓派快捷部署与自动更新：**下载并执行 [`scripts/install-docker.sh`](scripts/install-docker.sh)。脚本显示六个部署阶段、下载进度及每五秒的等待提示；配置下载、镜像拉取和服务启动分别设置超时，失败会标明阶段和退出码。首次配置 Watchtower 每五分钟检查新版；重新运行保留非空配置文件、已有 Compose 项目和 `/data` 数据卷。已安装 Docker Compose 的 64 位树莓派可执行 `bash scripts/install-docker.sh`；自定义目录使用 `DUO_INSTALL_DIR`。安装器的离线回归覆盖下载中断、原配置保留及拉取 / 启动失败。

## 最简单的购买流程：抛光布

以下为 Web 界面操作截图，使用模拟账号和订单；示例二维码不可付款，金额与状态以实际结账结果为准。

### 1. 正常登录

添加 Apple 账号，输入密码，按提示完成设备或短信验证码。已有账号先勾选，再点击“检查并使用所选账号”。

首次验证后自动保存 Apple 下发的设备信任，下次登录优先复用；只有信任失效或 Apple 再次要求时才输入验证码。设备信任与“保存密码”独立，移除账号会同时清除本机信任；旧 Python 配置导入时也会保留有效信任。

**541 与会话维护：**“官网登录恢复（保留账号）”从官网首页菜单取得本次登录链接，完成商城交换后再核验账号，保留账号和浏览器资料。自动空闲预热每十分钟用原浏览器无头刷新首页、购物袋和账号会话，适用于 Docker，再同步官网当前 Cookie；不会因已有浏览器校验 Cookie 就跳过刷新，也不在后台重新提交密码或验证码。自提预热先完成同样的会话核验，再按原规则准备。该调整修复了新增与恢复的入口差异及预热复用旧上下文的问题，不能保证 Apple 不再返回 541；流程与验证边界见 [官网恢复与空闲会话刷新](docs/STOREFRONT-SESSION-RECOVERY.md)。

![添加并登录账号](docs/images/purchase-01-login.png)

### 2. 选择抛光布

在工作台的“预制商品”选择 **抛光布 · MLH74FE**，数量先设为 **1**，点击“立即下单”。

![选择抛光布与数量](docs/images/purchase-02-product.png)

### 3. 按提示继续结账

选择配送 / 自提、地址等并继续。核对商品、数量、收货信息和总金额，再点击“确认创建订单”，直到显示付款二维码。结账可能包含购物袋里已有的其他商品，请核对完整清单。

![核对商品与金额并确认订单](docs/images/purchase-03-confirm.png)

### 4. 扫码支付

在实际运行中，用支付宝扫描程序显示的二维码并完成付款。**下图仅为演示，请勿扫码支付。**

![付款二维码演示，不可付款](docs/images/purchase-04-payment.png)

### 5. 查询订单

打开“订单”，点击“查询订单”；也可点击付款码下方的“我已支付，查询订单”。确认商品、数量及官网返回的状态，只有待付款订单不代表付款成功。

官网账号列表可能漏列刚创建的订单。程序会用当前账号列表实际提供的详情路径，另行核实本机记录的最近订单；只有官网详情中的订单号和商品数据匹配后才补充显示，点击订单号可打开官网详情。未能核实的本地记录不会作为有效订单加入。

取消订单也会查找未列出的订单详情；仅在官网允许取消、核对待付款状态并经界面确认后提交一次。提交超时只查询结果，不重复取消。超过付款期限的订单显示“已过期”，不冒充取消成功，并隐藏对应的旧付款码。

![查询订单并确认状态](docs/images/purchase-05-orders.png)

**移除本地账号：**在账号选择页点击账号旁的“移除”，或进入工作台 → 账号与登录 → “移除账号”，确认后清除该账号在本机的数据和保存密码。未完成登录的账号也可移除；执行中的任务需先完成或取消。官网账号和订单、其他账号、通用预设不受影响。

## 预设 SKU 与快捷地址

**保存购买预设：**左侧打开“本地配置”，选择配置范围，在“预制商品”选择已有商品，或选“自定义 SKU”后填写 SKU 和数量，点击“保存购买预设”。

**扩充内置商品列表：**在 [`src/products.ts`](src/products.ts) 的 `presetProducts` 中，照抛光布条目的格式添加 `sku`、`name`、`price`，然后重新构建。`price` 仅作参考，支付金额以官网结账结果为准；本地保存自定义 SKU 不会自动新增下拉列表条目。

**配置快捷物流地址：**在“本地配置”填写姓名、通知邮箱、手机号、省市区和详细地址，点击“保存地址预设”。结账时选择“为我送货”，再选择使用本地快捷地址；仍可选择官网已有地址。

**工作台布局：**“抢购准备”位于“购买商品”上方，集中放置预热登录、重新验证设备、提前准备及清空购物袋入口；购买区域仅保留送货与自提下单按钮。

**自提前准备：**商品已允许加购时，可点击“提前准备自提（不下单）”，提前完成门店、取货时段、联系人和支付宝选择。准备完成后，当前账号的任务保留会话最多五分钟；在任务中点击“立即下单（已准备自提）”才会重新读取官网核对并提交，点击“结束准备”或超时均不下单。等待期间该账号不能执行其他任务，已有定时抢购时不能开启此准备；其他账号可正常使用。若官网复核页没有足够门店或联系人信息，程序会按官网提供的编辑入口重新选择或填写，或重新核对购物袋后结账，不重复加购。商品、数量、门店、金额或配置发生变化时停止并要求重新准备；重启不会恢复或自动提交等待中的准备。此准备不保证库存，商品尚不能加购时请先使用“预热登录（不加购）”。原“提前准备（不下单）”仍用于送货。

**定时抢购：**在工作台选择商品和数量，再在“定时抢购”设置北京时间（精确到秒）及送货 / 自提，点击“设定定时抢购”。等待时显示倒计时并可取消；商品、数量和收货方式按设定时固定，地址或门店及联系人使用执行时已保存的本地预设。定时由本地服务等待，关闭网页后仍可继续，但需保持启动程序运行、电脑唤醒。等待期间不占账号执行锁，可预热登录；到点账号仍忙或迟到超过 3 秒时停止，不排队补发。退出或重启本地服务会停止定时，不自动补跑。每个账号仅允许一项未完成的定时抢购，取消后才可另设或立即购买；到点仅触发一次正常下单链路，沿用现有核对与失败恢复，不循环创建订单。下单耗时从实际触发开始统计，不把定时等待计入。

**管理购物袋：**购物袋页提供“清空购物袋”。先读取官网当前商品并展示确认清单；确认后只移除清单中的商品，逐条读取验证结果。购物袋发生变化时停止；移除超时先查当前状态，不自动重放删除，不取消已有订单，也不创建新订单。单品购买会在加购和结算前核对购物袋，存在其他商品时立即提示实际清单，避免走完整个结算流程后才发现不匹配。

**配置自提：**在“本地配置 → 自提门店与时段偏好”选择固定单店，或预选多家门店并调整先后顺序。可设最早、最晚可用时段，或每日时间范围及无匹配时的处理方式。保存门店和时段偏好不再要求填满本地联系人；选择优先使用官网联系人时，仅复用官网本次已确认的信息，仍缺少的必需项才提示补充。证件要求继续按官网执行，不填写完整证件号。

开启自动监控时仍可“从官网读取门店”，共享已有匿名代理池。点击“监控预选门店，有货自动下单”会先保存偏好，再合并本账号的监控目标；同一账号、商品和数量的候选池只生成一次购买意图，按预设顺序择一门店。每个任务仍按已设下单路数执行，默认 1 路。旧固定单店模式继续按门店独立监控和排队。

工作台“立即下单”走送货，“立即下单（自提）”执行自提偏好。结账重新核对准确商品、数量、门店、官网有效签名时段、联系人、金额及支付宝；不会选择预选范围外的门店或自动改送货，提交未知不换店重下。自提前准备仍在继续时重新读取并核对官网，不能跨店复用旧预约签名。协议依据、使用方法和边界见[自提偏好说明](docs/PICKUP-PREFERENCES.md)。

配置范围选“通用预设”时，只供之后添加的新账号继承；选择具体账号则只修改该账号。地址预设保存在本机，不会直接修改官网地址簿。

## 构建

在目标系统及对应架构上构建，不能直接把 Mac 产物拿到 Windows 使用。先准备上述开发环境。

### macOS

```sh
pnpm install --frozen-lockfile
pnpm worker:setup
pnpm worker:build
pnpm bundle
```

输出：`src-tauri/target/release/bundle/macos/DUO Killer.app`。

当前构建未配置发行签名和公证。若首次打开提示无法验证开发者，确认来源可信后，先尝试打开一次，再到 **系统设置 → 隐私与安全性 → 仍要打开**，确认“打开”。此方法针对未认证开发者提示；不要忽略恶意软件或损坏警告。参见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。

### Windows

安装 Visual Studio C++ Build Tools，勾选“使用 C++ 的桌面开发”，并安装 WebView2；详见 [Tauri 前置要求](https://v2.tauri.app/zh-cn/start/prerequisites/)。在 PowerShell 中进入项目目录，执行：

```powershell
pnpm install --frozen-lockfile
pnpm worker:setup
pnpm worker:build
pnpm bundle
```

输出：`src-tauri/target/release/bundle/portable/DUO Killer/`。打开其中的 `DUO Killer.exe`，分享时保留整个目录及内置 worker。

### 构建 Web 版

在 macOS 或 Windows 的项目目录执行：

```sh
pnpm install --frozen-lockfile
pnpm build:web
```

输出：`local-web-release/`，复制整个目录给相同系统和架构的电脑使用。项目也提供 [桌面构建 CI](.github/workflows/build.yml)、[Web 构建 CI](.github/workflows/local-web.yml) 和 [GHCR 双架构镜像 CI](.github/workflows/ghcr.yml)。

## 开发与验证

项目使用 React / TypeScript 共用界面、Rust 任务引擎和 Python worker。Apple 交互采用专用浏览器获取或恢复会话、Python 推进官网网页 HTTP 结账协议的方式；自动化可推进到待付款订单，支付由本人扫码完成。源码具备这些流程不代表每次真实登录、库存查询或下单都成功。

| 目录 | 开发职责 |
| --- | --- |
| `src/` | 桌面与 Web 共用界面、桥接及状态展示。 |
| `src-tauri/src/` | 共享任务引擎、账号隔离、队列及桌面宿主。 |
| `local-web/` | 复用共享引擎的本地 HTTP 服务。 |
| `worker/` | Python 任务、库存与会话；`legacy/` 保存官网协议实现。 |
| `scripts/`、`tests/` | 开发启动、打包、离线回归与浏览器验证。 |
| `docker/`、`.github/workflows/` | 容器、桌面 / Web 构建及双架构发布。 |

日常开发使用 `pnpm dev:web`，默认端口为 1421。需要隔离环境时使用 `pnpm dev:web --no-open --port 1439 --data-dir artifacts/dev-isolated`，避免占用实际账号数据；`pnpm dev` 只启动前端。Windows PowerShell 如遇执行策略限制，可使用 `pnpm.cmd`。

| 验证目标 | 命令 |
| --- | --- |
| 前端类型与构建 | `pnpm build` |
| Python worker | 首次 `pnpm worker:setup`，随后 `pnpm test:worker` |
| Web 与共享 Rust 引擎 | `cargo test --locked --manifest-path local-web/Cargo.toml` |
| 桌面 Rust | `cargo test --locked --manifest-path src-tauri/Cargo.toml`，需目标平台构建依赖 |
| 界面回归 | 首次 `pnpm exec playwright install chromium`，随后 `pnpm test:ui` |
| Web 开发启动 | `pnpm test:dev:web`，仅 `dev.spec.ts` |
| Web 分发包 | `pnpm build:web` 后 `pnpm test:web`；Web 浏览器测试另用 `pnpm test:web:ui` |
| 既定格式检查 | `pnpm check:format`，范围以 `package.json` 中的脚本为准 |

`pnpm test` 只执行前端构建和界面回归，不包含 worker 与 Rust 测试。按改动范围运行相应检查；文档变更检查链接、命令和事实即可。两套 Cargo 清单和锁文件需一起维护，当前 `uuid = "=1.26.0"` 保留 Rust 1.88 兼容。离线 fixture、容器健康和只读查询均不能代替真实登录、订单创建或付款验证，历史验收记录也不代表当前版本已复测。

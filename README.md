# DUO Killer · iPhone DUO 抢购辅助与 Apple 商城快速下单

面向 **iPhone DUO 抢购准备与快速下单** 的 Apple 中国在线商店辅助工具，支持 **macOS、Windows 和本地 Web**。提前配置账号、商品 SKU、购买数量和收货地址，在同一个界面完成登录检查、加入购物袋、结账确认、生成付款二维码和订单查询。

iPhone DUO launch assistant and Apple Store quick checkout tool for macOS, Windows and local Web. Built with Tauri, Rust, React and Python.

本仓库基于 [Jasper-zzq/iPhoneDuo](https://github.com/Jasper-zzq/iPhoneDuo) 的本地修改版本，包含结算提速、失败状态核对恢复及订单取消。按本次所选商品和数量自动结算，无独立商品授权白名单、固定数量或金额上限；不附加 AppleCare+。地址按账号独立保存，价格、库存和实际限购数量以官网返回为准。旧 `automation.json` 不再作为下单条件。

**0.1.18 已验证密码保留：**修复同一任务先登录成功、随后再次认证 401 导致已存密码和缓存被清除的问题。已验证密码跨任务保留，新候选被拒绝不封锁原有效记录；保存后实际读取校验，日志可核对保存与复用状态。已验证密码的当前认证拒绝可在原 Checkout / 动态入口内由原浏览器恢复一次，维护中的后续购物袋查询失败也不再误报为需要密码。详见 [已验证凭据保留与认证归属](docs/VERIFIED-CREDENTIAL-RETENTION.md)。

**0.1.17 登录与凭据修复：**App 密码按账号即时复用，保存选择跨任务保留；官网确认本次密码后即可保存，不再等待后续下单成功。通用认证错误、541、浏览器预填或焦点中断不会清除另一份 App 密码。恢复、维护和购买前核验复用有效会话，真正需要登录时优先沿用首次登录协议与设备信任；六位验证码及缺少的密码统一在当前 App 任务输入。合并浏览器逐字校验减少往返，并修复密码提示后的字段重建及监控负数等待自动停止。详见 [登录与凭据生命周期](docs/LOGIN-CREDENTIAL-LIFECYCLE.md)。

**0.1.16 每日监控时段：**支持每天“时段内暂停”或“仅时段内检测”，例如北京时间 `01:00–05:00` 暂停、`05:00` 自动恢复，支持跨午夜。规则保存在服务器并跨重启生效；只控制库存检测，已入队购买继续执行。详见 [每日检测时段](docs/MONITOR-SCHEDULE.md)。

**0.1.15 登录恢复与输入提速：**修复常驻浏览器第二次操作时后台任务页未激活、正常页面更新和输入前字段重建导致的输入中断；同步 HTTP 与常驻浏览器的商城会话，保留较新的浏览器状态和 Cookie 属性。账号、密码、验证码、远程输入和鼠标点击统一移除 100–200ms 人为随机延时；保留页面、账号和焦点核验。下单继续优先复用登录态，明确需要认证时才恢复。诊断与验证范围见 [登录态同步与输入恢复](docs/LOGIN-STATE-INPUT-RECOVERY.md)。

**0.1.13 快速自提架构：**Docker 按账号常驻 Chrome；空闲自提准备保留原 worker、Session 和 Checkout，手动、定时与监控通过同一入口接手。预选门店分别入队并归属同一次购买目标，成功后停止同组剩余任务。自提统一选择上海时间今天起 7 个自然日内的最早有效时段，包括明天及后续日期。准备命中不代表已下单，三秒是待现场验证的性能目标。参见 [整体架构与验收](docs/FAST-PICKUP-ARCHITECTURE.md) 和 [准备交接协议](docs/PREPARED-HANDOFF.md)。

## 主要功能

| 功能 | 说明 |
| --- | --- |
| iPhone DUO 发售状态与库存监控 | 无需 Apple 登录读取发售提示；可从接口选多家门店，按 1–300 秒间隔监控实际库存（默认 1 秒）并联动自提抢购。未知状态不代表有货。 |
| 商品与数量预设 | 内置 Duo 白色 256GB、512GB、iPhone 18 Pro 银色 256GB 与抛光布 SKU，默认数量为 1。 |
| 快速下单 | 自动送货并使用本地地址和联系方式；核对商品、数量、地址、金额与支付宝后创建订单。 |
| 临时失败恢复 | 送货、地址、支付方式失败后先读取当前结算状态，已完成则继续，仍在原步骤且允许继续时有限重试。 |
| 重复下单 | 加购与最终下单请求不自动重发；人工再次下单仍由 Apple 判断是否接受。自动队列遇到未知提交时停止该账号后续派发，先核对官网结果。 |
| 多账号独立运行 | 每个账号独立保存会话、设备信任和浏览器配置；不同账号可以并行操作，验证码与确认提示标明所属账号。 |
| 登录与设备信任 | 支持设备验证码、短信验证码及官网浏览器登录，保存并复用当前账号有效的设备信任；需要重新认证时按提示完成登录。 |
| 配送与门店自提 | 可使用官网已有地址或本地快捷地址，支持选择官网返回的可取货门店。 |
| 支付与订单查询 | 确认下单后立即展示订单信息，随后加载支付宝二维码；支持查询及取消官网允许取消的未付款订单。 |
| 手机 PWA 与后台通知 | 默认密码保护的 HTTPS Quick Tunnel；库存变化通知及每分钟待付款提醒，最长 30 分钟。 |
| 顺序自提 | 同账号每次只执行一路；不同账号可并行。保留 0–10 次额外串行重试，已有订单或提交未知即停止。 |
| 自动执行队列 | 新鲜有货信号触发 FIFO 排队，默认逐个执行，也可固定并发；入队后不受后续监控无货、未知或样本过期影响，实际下单失败记录真实原因并按配置重试。队列最多同时执行 10 个不同账号，仍遵循所选全局顺序/并行模式。 |
| 运行日志与会话恢复 | 按账号、任务、类别查看结构化日志；保留原账号和浏览器资料恢复官网会话，PWA 可操作当前任务的官方浏览器窗口。 |

**DUO 使用流程：**提前配置账号与地址、预热登录 → 刷新发售状态 → 选择商品 → 立即下单 → 自动核对并创建订单 → 扫码支付 → 查询订单。

发售提示可手动刷新，实际库存可持续监控；库存、价格和是否可购买以 Apple 实际返回为准，付款由本人扫码完成。

**手机远程入口：**安装官方 `cloudflared` 后运行 `pnpm pwa` 或双击 `start-pwa.cmd`，启动器保留已有 Web 账号数据并显示 HTTPS 地址与默认密码。手机添加到主屏幕后启用通知。参见 [自动监控、并发自提与 PWA](docs/MONITOR-PWA.md)。

**官网登录远程画面（0.1.4）：**官网画面通过 CDP 实时帧流采集，Web / PWA 通过 WebSocket 推送；页面静止时由连接心跳确认可操作，不再因截图时间或手机与服务器时钟差而反复锁定。断线或页面切换时暂停发送，恢复连接后重新确认当前画面；保留未发送草稿，任务结束或切换账号时清除。支持空格、点击、滚动和键盘输入。详见 [官网实时画面与输入](docs/REMOTE-BROWSER-PREVIEW.md)。

**队列与账号会话：**队列按最新倒序显示、实际保持 FIFO；到货信号入队后正常执行，后续监控无货不会让任务等待库存；关闭授权后保留未执行任务，手动取消仍有效。账号下单空闲 10 分钟后执行“预热登录（不加购）”，手动、定时和监控下单优先。通知、密码及安装入口统一放在“应用设置”，自动监控提供最近有货事件列表。使用流程、持久化 ACK 和恢复边界见 [执行队列、结构化日志与官网会话恢复](docs/QUEUE-LOGS-SESSION.md)。

**统一界面与手机操作：**全局下拉使用同一组件，数量、并发和重试使用可输入的加减步进器；手机触摸区域至少 44px。最近有货按“时间、型号、门店”列表展示，队列和日志减少嵌套卡片，商品及订单表格适配窄屏。设计与截图审查、验证范围见 [界面统一与手机适配](docs/UI-CONSISTENCY-REVIEW.md)。

**下单进度与紧凑列表：**顶部固定显示当前下单步骤，可切换账号任务并前往处理；待付款和提交未知分别突出提醒。执行队列优先展示商品、当前步骤及失败原因；运行日志按毫秒时间、彩色级别和单行内容扫读，点按展开完整信息。展开器统一为 SVG 箭头，监控设置展开时保持标题和操作位置稳定。详见 [下单进度、日志与展开交互](docs/INTERACTION-REFINEMENT.md)。

**入队方式、时间与购买选择：**预选多店按有货门店分别入队并归入一次购买目标，同批按用户门店顺序派发，成功后停止同组其余任务；原独立单店授权保持兼容。任务的入队时间、首次发现有货、开始下单与收到订单号分层显示，历史缺失不会用刷新时间代替。顶部进度栏紧凑展示真实失败原因，已完成步骤绿、失败步骤红。购买面板的商品与目标数量按账号保存在浏览器 localStorage，任务结束和刷新后保留。行为、恢复方式及验证见 [交互说明](docs/INTERACTION-REFINEMENT.md)。

**监控随应用重启恢复：**此前开启的监控在本地 Web 或桌面程序重启后自动恢复，重新读取已保存的目标并查询库存，按原自动下单授权处理新鲜有货；点击“停止监控”后重启仍保持关闭。手动暂停队列、已取消任务及待核实订单继续有效，已派发的旧购买不会重放。详见 [监控重启恢复](docs/MONITOR-RESTART.md)。

## 快速启动（Web）

**使用源码：**准备 Node.js 22.22+、pnpm 11.9、Rust stable、Python 3.10+（建议 3.12）。macOS 需 Xcode Command Line Tools，Windows 需 MSVC C++ Build Tools。具体安装见 [Tauri 前置要求](https://v2.tauri.app/zh-cn/start/prerequisites/)。

克隆仓库后启动：

```sh
git clone https://github.com/fantasy194/applestore_shot.git
cd applestore_shot
pnpm install --frozen-lockfile
pnpm dev:web
```

程序自动准备 Python 环境、编译本地服务并打开浏览器。在启动终端按 **Ctrl+C** 退出服务；仅关闭网页不会退出服务。

**使用构建好的 Web 版：**macOS 双击 `local-web-release/启动.command`，Windows 双击 `local-web-release/start.cmd`。保留整个目录，无需安装开发环境。

**Docker Compose：**在项目目录执行 `docker compose up -d --build --wait`，打开 `http://127.0.0.1:17654`，从 `docker compose logs app` 获取首次访问密码。自 0.1.3 起，Compose 同时启动应用和基于 [jlesage/chromium](https://github.com/jlesage/docker-chromium) 的浏览器容器；添加账号、官网登录及预热通过私有 CDP 通道操作独立账号浏览器，沿用 `/data` 中的资料。两种镜像均支持 `linux/amd64` 和 `linux/arm64`，不向主机发布 CDP 或 VNC。GitHub Actions 在推送 `main` 或 `v*` 标签时分别验证两种架构，发布应用的 `latest` 和配套的 `latest-browser` 镜像。旧单容器部署需先更新 Compose 配置，单独更新应用镜像仍沿用原内置浏览器。升级和数据保留说明见 [Docker 本地部署](docker/README.md)。

**树莓派快捷部署与自动更新：**下载并执行 [`scripts/install-docker.sh`](scripts/install-docker.sh)。脚本显示六个部署阶段、下载进度及每五秒的等待提示；配置下载、镜像拉取和服务启动分别设置超时，失败会标明阶段和退出码。首次配置 Watchtower 每五分钟检查应用与浏览器新版。重新运行会备份并升级未修改的官方 Compose 配置，保留自定义配置、已有项目及 `/data` 数据卷；自定义部署按 Docker 文档合并浏览器服务后再更新。已安装 Docker Compose 的 64 位树莓派可执行 `bash scripts/install-docker.sh`；自定义目录使用 `DUO_INSTALL_DIR`。安装器的离线回归覆盖旧配置升级、自定义配置保留、下载中断及拉取 / 启动失败。

**自动更新诊断（0.1.5）：**安装器识别已发布的官方 Compose 配置并安全迁移；Watchtower 可只读使用宿主的注册表配置目录，支持配置日志级别以查明检查跳过的原因。`skipped` 不代表已是最新版，需核对容器提交、健康状态及网页版本；旧单容器部署仍须先合并浏览器服务。目录选择、临时诊断及保留数据更新步骤见 [Docker 自动更新说明](docker/README.md)。

**监控信号与下单解耦（0.1.8）：**新鲜有货信号触发排队后，后续监控无货、未知或样本变旧均不拦截执行，移除原库存时效检查开关。结账按官网实际结果记录失败，并沿用已配置的额外重试次数；重试默认 0、最多 10 次，已有订单、提交未知或需要认证时停止。手动取消、授权范围和重启恢复保护继续有效。手动和队列购买在加购前通过原浏览器核对官网当前会话，后台预热的正常状态不替代本次购买核验；541、挑战和提交未知继续停止并记录原因。详见[队列说明](docs/QUEUE-LOGS-SESSION.md)与[购买前会话核验](docs/PURCHASE-SESSION-CHECK.md)。

**自动会话与快速购买（0.1.10）：**空闲时主动维护浏览器会话；购买先只读快速核验当前账号，失效时自动用保存的凭据恢复登录。后台预热间隔、旧冷却和历史需登录状态不再阻止购买；队列取消认证失败后的手动解锁门槛，自动恢复仍失败时保留真实失败结果。手动、定时和队列共用购买执行器；并发子路遇到结账认证时也能在原会话继续，不再硬性拒绝。六位验证码在当前任务输入后继续，无需另开恢复任务；后台失败按十分钟空闲节奏再次尝试。旧版本因认证暂停被放回队列的已失败任务在升级时终结，不补跑；真正未执行的队列保留。已有订单或提交未知仍不自动重放。详见[自动会话核验](docs/PURCHASE-SESSION-CHECK.md)和[购买流程一致性](docs/PURCHASE-FLOW-PARITY.md)。

**结账认证自动接管（0.1.12）：**本次结账商城认证交换返回 541 且尚未提交时，自动由原账号浏览器接管当前官网登录入口，继续使用现有凭据及同一验证码任务；取得实际结算页面后回到原购买继续。手动、定时、队列与隔离子路共用恢复行为，不重加购、不重新创建购买，也不重放已提交订单。恢复成功后保存核验后的最新会话，供后续购买复用；541 不再一律清空商城认证状态。详见[结账浏览器恢复](docs/CHECKOUT-BROWSER-RECOVERY.md)。

**官网恢复等待与入口一致性（0.1.11）：**手动恢复、购买前自动恢复和空闲维护共用页面等待与认证助手。菜单显示已登录后，等待当前账号页的 Cookie 更新、延迟跳转或官网认证 iframe，不再在页面刚加载时直接要求人工；需要认证时继续同一浏览器和当前任务。无认证时不重复读取账号页，实际认证后再核对一次身份。实际下单按钮和服务端统一允许购买接管后台维护与明确的登录预热；新建定时不被维护验证码挡住，已排队购买优先于新预热。成功认证后的普通缺货按原重试配置处理，历史 541 标记不再单独阻止有效会话。详见[官网会话恢复](docs/STOREFRONT-SESSION-RECOVERY.md)。

**配置与密码保存（0.1.7）：**本地配置统一读取服务器完整配置，直接刷新、清空浏览器存储和切页均使用同一来源；读取完成前不能保存，避免空表单覆盖。Docker 可启用按账号加密的持久密码库，主密钥独立只读挂载，仅在勾选保存且登录成功后持久化，重启和镜像升级继续复用。官网登录恢复接受同一官方动态登录链接的重复菜单项；已登录菜单仅做一次官方账号只读核验，认证挑战仍交由本人处理。详见[配置修复](docs/LOCAL-SETTINGS-PERSISTENCE-FIX.md)、[Docker 密码库](docker/README.md)和[官网恢复](docs/STOREFRONT-SESSION-RECOVERY.md)。

**会话与远程操作（0.1.6）：**应用中输入的密码按账号在本次服务运行期间跨任务复用，明确密码错误、忘记密码或移除账号时清除；不新增明文密码文件，服务重启后是否可用仍取决于凭据保险库及浏览器登录态。空闲预热新增“官网登录恢复（保留账号）”，三种后台流程统一无头，人工登录保持可见窗口。远程画面在代理不支持 WebSocket 时使用同一增量事件的 HTTP 备用通道，区分明确拒绝与结果未确认的输入，不自动重放操作。旧队列仅依据已保存的首次库存样本恢复有货时间。详见 [官网登录助手](docs/BROWSER-LOGIN-AUTOFILL.md)与[远程窗口](docs/REMOTE-BROWSER-PREVIEW.md)。

**浏览器上下文连接：**添加账号、官网登录恢复和预览共用有界的分阶段 CDP 连接，等待端口就绪后再完整连接，避免树莓派慢启动被旧的 1 秒超时误判为配置占用。连接失败会区分原因并保留账号资料；双架构镜像新增真实浏览器的慢握手、预览输入和资料重启回归。说明见 [浏览器连接诊断与验证](docs/BROWSER-CDP-STARTUP.md)。

**Docker 局域网访问：**可配置 `DUO_WEB_BIND=0.0.0.0`，使用原 Web 密码登录。由网络或反向代理控制入口时，设置 `DUO_WEB_TRUST_NETWORK=1` 可关闭 Host/Origin 校验，允许任意访问域名；也可保留默认检查并使用精确的 `DUO_WEB_ALLOWED_ORIGINS`。Docker 默认停用 Quick Tunnel；配置示例及主机目录持久化说明见 [树莓派局域网访问](docker/README.md#树莓派局域网访问)。

## 最简单的购买流程：抛光布

以下为 Web 界面操作截图，使用模拟账号和订单；示例二维码不可付款，金额与状态以实际结账结果为准。

### 1. 正常登录

添加 Apple 账号，输入密码，按提示完成设备或短信验证码。已有账号先勾选，再点击“检查并使用所选账号”。

首次验证后自动保存 Apple 下发的设备信任，下次登录优先复用；只有信任失效或 Apple 再次要求时才输入验证码。设备信任与“保存密码”独立，移除账号会同时清除本机信任；旧 Python 配置导入时也会保留有效信任。

**541 与会话维护：**“官网登录恢复（保留账号）”从官网首页菜单取得本次登录链接，完成商城交换后再核验账号，保留账号和浏览器资料。自动空闲预热每十分钟用原浏览器无头刷新首页、购物袋和账号会话，适用于 Docker；需要普通登录时，在官网页面使用可用密码自动填写并继续，验证码和其他安全挑战交由本人处理。首次官网浏览器登录也共用此流程，输入通过鼠标和逐字键盘事件完成，统一使用随机 100–200 ms 延时；新增账号、官网登录恢复和预热复用同一登录助手。远程窗口提供“使用现有凭证登录”，可继续未提交的登录步骤，密码只从当前任务或系统凭据库读取，不传回页面。自提预热先完成同样的会话核验，再按原规则准备。该调整不能保证 Apple 不再返回 541；见 [官网恢复与空闲会话刷新](docs/STOREFRONT-SESSION-RECOVERY.md)及[官网自动填写](docs/BROWSER-LOGIN-AUTOFILL.md)。

## 预设 SKU 与快捷地址

**保存购买预设：**左侧打开“本地配置”，选择配置范围，在“预制商品”选择已有商品，或选“自定义 SKU”后填写 SKU 和数量，点击“保存购买预设”。

**扩充内置商品列表：**在 [`src/products.ts`](src/products.ts) 的 `presetProducts` 中，照抛光布条目的格式添加 `sku`、`name`、`price`，然后重新构建。`price` 仅作参考，支付金额以官网结账结果为准；本地保存自定义 SKU 不会自动新增下拉列表条目。

**配置快捷物流地址：**在“本地配置”填写姓名、通知邮箱、手机号、省市区和详细地址，点击“保存地址预设”。结账时选择“为我送货”，再选择使用本地快捷地址；仍可选择官网已有地址。

**工作台布局：**“抢购准备”位于“购买商品”上方，集中放置预热登录、重新验证设备、提前准备及清空购物袋入口；购买区域仅保留送货与自提下单按钮。

**自提前准备：**商品已允许加购时，可点击“提前准备自提（不下单）”，提前完成门店、取货时段、联系人和支付宝选择。准备完成后，当前账号的任务保留会话最多五分钟；在任务中点击“立即下单（已准备自提）”才会重新读取官网核对并提交，点击“结束准备”或超时均不下单。等待期间该账号不能执行其他任务，已有定时抢购时不能开启此准备；其他账号可正常使用。若官网复核页没有足够门店或联系人信息，程序会按官网提供的编辑入口重新选择或填写，或重新核对购物袋后结账，不重复加购。商品、数量、门店、金额或配置发生变化时停止并要求重新准备；重启不会恢复或自动提交等待中的准备。此准备不保证库存，商品尚不能加购时请先使用“预热登录（不加购）”。原“提前准备（不下单）”仍用于送货。

**定时抢购：**在工作台选择商品和数量，再在“定时抢购”设置北京时间（精确到秒）及送货 / 自提，点击“设定定时抢购”。等待时显示倒计时并可取消；商品、数量和收货方式按设定时固定，地址或门店及联系人使用执行时已保存的本地预设。定时由本地服务等待，关闭网页后仍可继续，但需保持启动程序运行、电脑唤醒。等待期间不占账号执行锁，可预热登录；到点账号仍忙或迟到超过 3 秒时停止，不排队补发。退出或重启本地服务会停止定时，不自动补跑。每个账号仅允许一项未完成的定时抢购，取消后才可另设或立即购买；到点仅触发一次正常下单链路，沿用现有核对与失败恢复，不循环创建订单。下单耗时从实际触发开始统计，不把定时等待计入。

**管理购物袋：**购物袋页提供“清空购物袋”。先读取官网当前商品并展示确认清单；确认后只移除清单中的商品，逐条读取验证结果。购物袋发生变化时停止；移除超时先查当前状态，不自动重放删除，不取消已有订单，也不创建新订单。单品购买会在加购和结算前核对购物袋，存在其他商品时立即提示实际清单，避免走完整个结算流程后才发现不匹配。

**配置自提：**在“本地配置 → 自提门店与时段偏好”选择固定单店，或预选多家门店并调整先后顺序。可设最早、最晚可用时段，或每日时间范围及无匹配时的处理方式。保存门店和时段偏好不再要求填满本地联系人；选择优先使用官网联系人时，仅复用官网本次已确认的信息，仍缺少的必需项才提示补充。证件要求继续按官网执行，不填写完整证件号。

开启自动监控时仍可“从官网读取门店”，共享已有匿名代理池。点击“监控预选门店，有货自动下单”会先保存偏好，再合并本账号的监控目标；同一账号、商品和数量的候选池只生成一次购买意图，按预设顺序择一门店。每个任务仍按已设下单路数执行，默认 1 路。旧固定单店模式继续按门店独立监控和排队。

工作台“立即下单”走送货，“立即下单（自提）”执行自提偏好。结账重新核对准确商品、数量、门店、官网有效签名时段、联系人、金额及支付宝；不会选择预选范围外的门店或自动改送货，提交未知不换店重下。自提前准备仍在继续时重新读取并核对官网，不能跨店复用旧预约签名。协议依据、使用方法和边界见[自提偏好说明](docs/PICKUP-PREFERENCES.md)。

配置范围选“通用预设”时，只供之后添加的新账号继承；选择具体账号则只修改该账号。地址预设保存在本机，不会直接修改官网地址簿。

## 构建

在目标系统及对应架构上构建，不能直接把 Mac 产物拿到 Windows 使用。先准备上述开发环境。

### macOS

```sh
pnpm install --frozen-lockfile
pnpm worker:setup
pnpm worker:build
pnpm bundle
```

输出：`src-tauri/target/release/bundle/macos/DUO Killer.app`。

当前构建未配置发行签名和公证。若首次打开提示无法验证开发者，确认来源可信后，先尝试打开一次，再到 **系统设置 → 隐私与安全性 → 仍要打开**，确认“打开”。此方法针对未认证开发者提示；不要忽略恶意软件或损坏警告。参见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。

### Windows

安装 Visual Studio C++ Build Tools，勾选“使用 C++ 的桌面开发”，并安装 WebView2；详见 [Tauri 前置要求](https://v2.tauri.app/zh-cn/start/prerequisites/)。在 PowerShell 中进入项目目录，执行：

```powershell
pnpm install --frozen-lockfile
pnpm worker:setup
pnpm worker:build
pnpm bundle
```

输出：`src-tauri/target/release/bundle/portable/DUO Killer/`。打开其中的 `DUO Killer.exe`，分享时保留整个目录及内置 worker。

### 构建 Web 版

在 macOS 或 Windows 的项目目录执行：

```sh
pnpm install --frozen-lockfile
pnpm build:web
```

输出：`local-web-release/`，复制整个目录给相同系统和架构的电脑使用。项目也提供 [桌面构建 CI](.github/workflows/build.yml)、[Web 构建 CI](.github/workflows/local-web.yml) 和 [GHCR 双架构镜像 CI](.github/workflows/ghcr.yml)。

## 开发与验证

项目使用 React / TypeScript 共用界面、Rust 任务引擎和 Python worker。Apple 交互采用专用浏览器获取或恢复会话、Python 推进官网网页 HTTP 结账协议的方式；自动化可推进到待付款订单，支付由本人扫码完成。源码具备这些流程不代表每次真实登录、库存查询或下单都成功。

| 目录 | 开发职责 |
| --- | --- |
| `src/` | 桌面与 Web 共用界面、桥接及状态展示。 |
| `src-tauri/src/` | 共享任务引擎、账号隔离、队列及桌面宿主。 |
| `local-web/` | 复用共享引擎的本地 HTTP 服务。 |
| `worker/` | Python 任务、库存与会话；`legacy/` 保存官网协议实现。 |
| `scripts/`、`tests/` | 开发启动、打包、离线回归与浏览器验证。 |
| `docker/`、`.github/workflows/` | 容器、桌面 / Web 构建及双架构发布。 |

日常开发使用 `pnpm dev:web`，默认端口为 1421。需要隔离环境时使用 `pnpm dev:web --no-open --port 1439 --data-dir artifacts/dev-isolated`，避免占用实际账号数据；`pnpm dev` 只启动前端。Windows PowerShell 如遇执行策略限制，可使用 `pnpm.cmd`。

| 验证目标 | 命令 |
| --- | --- |
| 前端类型与构建 | `pnpm build` |
| Python worker | 首次 `pnpm worker:setup`，随后 `pnpm test:worker` |
| Web 与共享 Rust 引擎 | `cargo test --locked --manifest-path local-web/Cargo.toml` |
| 桌面 Rust | `cargo test --locked --manifest-path src-tauri/Cargo.toml`，需目标平台构建依赖 |
| 界面回归 | 首次 `pnpm exec playwright install chromium`，随后 `pnpm test:ui` |
| Web 开发启动 | `pnpm test:dev:web`，仅 `dev.spec.ts` |
| Web 分发包 | `pnpm build:web` 后 `pnpm test:web`；Web 浏览器测试另用 `pnpm test:web:ui` |
| 既定格式检查 | `pnpm check:format`，范围以 `package.json` 中的脚本为准 |

`pnpm test` 只执行前端构建和界面回归，不包含 worker 与 Rust 测试。按改动范围运行相应检查；文档变更检查链接、命令和事实即可。两套 Cargo 清单和锁文件需一起维护，当前 `uuid = "=1.26.0"` 保留 Rust 1.88 兼容。离线 fixture、容器健康和只读查询均不能代替真实登录、订单创建或付款验证，历史验收记录也不代表当前版本已复测。

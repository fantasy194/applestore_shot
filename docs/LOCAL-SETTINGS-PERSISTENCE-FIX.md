# 本地配置刷新恢复修复（0.1.7）

配置仍以应用服务端的数据文件为准。浏览器不新增本地配置副本；Docker 下“本地配置”指应用服务器的数据目录，刷新、换浏览器不会改变保存位置。

## 原因与读取规则

轻量工作区传输只提供任务摘要，省略地址读取/保存任务的 `result.config`。旧版设置页却直接从摘要取得表单配置；原地刷新后只有摘要，文件仍存在但表单为空。从工作台切入时，若内存里恰好留有刚完成任务的完整事件，便能回填，因此两个入口表现不同。已用相同 HTTP fixture 对照发布版本的 `LocalPages.tsx` 复现“服务端已有地址、表单为空”。

设置页只读取当前范围的最新成功配置任务详情，不拉全量历史或日志。没有历史任务时，仍发起服务器 `address_read`，并取得本次详情；较旧的地区查询不覆盖较新保存的地区。详情响应必须匹配任务、账号及当前修订，迟到响应不能覆盖当前范围。App 原有初始化完成门控已验证正确，单账号冷启动不额外回退到通用预设。

读取未完成、失败或返回无效配置时，地址和自提保存以及“保存并监控”均暂停，页面提供重试；明确读取到 `{}` 是有效空配置，可继续编辑。自提保存先完成服务器保存，再读取监控设置并应用授权，原有失败边界保留。

# 自动监控、并发自提与手机 PWA

继续使用 iPhoneDuo 现有登录、设备信任和 HTTP 结账。参考 `applestore_check` 的公开库存接口、动态代理生命周期和 Web Push 设计，新增匿名监控和远程界面。库存代理不接触账号 Cookie、验证码、购物袋和支付。

执行队列、结构化日志、官网恢复和空闲会话维护说明见 [执行队列、结构化日志与官网会话恢复](QUEUE-LOGS-SESSION.md)。多门店自提偏好和运行中共享门店查询已部署，当前验证结果及入口见[自提偏好验收记录](PICKUP-PREFERENCES-VERIFICATION.md)。

## 启动与密码

安装官方 [cloudflared](https://developers.cloudflare.com/tunnel/downloads/)，Windows 可放在 `.tools/cloudflared.exe`，或加入 PATH。源码依赖安装后：

```powershell
pnpm install --frozen-lockfile
pnpm pwa
```

也可双击 `start-pwa.cmd`。启动器编译静态网页和本地服务，启动 worker，再创建 HTTPS Quick Tunnel。终端显示网址和首次生成的默认密码；侧栏“应用设置”可管理通知、安装和访问密码。密码仅保存 Argon2 哈希。需要重设时，启动前设置环境变量 `DUO_WEB_PASSWORD`（8–128 字符）；重设后从终端环境移除此变量。

数据目录优先使用已有项目 `.local-data`，其次已有 `%APPDATA%/com.niulai.local-web-dev`、`%APPDATA%/com.niulai.local-web`。macOS 使用对应 `~/Library/Application Support/`。没有已有工作空间时使用项目 `.local-data`。可指定 `--data-dir`。同一数据目录只允许一个服务运行，不自动覆盖或清理原有浏览器资料。

```powershell
pnpm pwa --no-open
pnpm pwa --no-tunnel
pnpm pwa --skip-build
pnpm pwa --data-dir <目录>
pnpm pwa:stop
```

`--no-tunnel` 只启动本机，`--skip-build` 复用已构建程序。Ctrl+C 或 `stop-pwa.cmd` 正常退出。退出会取消本地监控/定时/执行任务；已提交订单仍须核对官网。首次密码和本机链接保留在数据目录 `server.log`，该文件不要分享。

已启动最新静态 Web 服务时，可仅连接隧道：

```powershell
pnpm tunnel --origin http://127.0.0.1:17653 --data-dir <数据目录> --log-file <启动日志>
```

入口只接受实际注册的准确隧道主机。未登录不能读取账号和业务 API；公共入口不能修改隧道或停止服务。本机启动令牌继续兼容旧流程。Vite 开发服务器不用于公网入口。Quick Tunnel 不支持 SSE，页面每秒短轮询更新，库存采样和提醒由本机服务执行。

[Cloudflare 官方限制](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)包括无可用性保证、最多 200 个处理中请求和重建后网址变化。网址变化需在新入口重新登录、安装并订阅通知；固定网址可改用命名隧道。

## 手机通知

1. 手机打开 HTTPS 地址并输入密码。
2. iPhone 用 Safari 分享菜单“添加到主屏幕”，从图标打开；其他支持的浏览器使用安装应用功能。
3. 打开侧栏“应用设置”，点击“启用通知”并允许，再点“测试通知”。各设备分别订阅。

库存变为确认可用时立即提醒，未知状态不会重复触发同次补货通知。核实的待付款订单立即提醒，此后每 60 秒提醒，最晚至确认后 30 分钟；更早的明确截止时间优先。相同订单重复事件、获取付款码和服务重启不会延长截止时间。点击查询订单会核对本地已知订单的官方详情；明确已支付、取消或过期后停止。60 秒是服务端发起间隔，实际投递由浏览器与系统决定。

Service Worker 接收真正的后台 Web Push，关闭页面仍可提醒，但需保持本机服务、隧道和电脑运行。通知不包含付款链接、二维码、Cookie和联系人。只缓存离线提示和图标，API和付款信息不缓存。iPhone 支持条件见 [Apple 文档](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers)。

## 多门店与账号联动

进入“自动监控”，或展开 DUO 状态页的门店监控，选择 SKU、每路数量、城市/六位邮编，从接口读取并勾选门店。返回的是此次搜索的附近门店，不是全国目录。抛光布 SKU 为 `MLH74FE`。

默认每秒一轮，可通过“监控检查间隔（秒）”设置 1–300 秒；修改前先停止监控，保存后按新间隔启动，重启后沿用已保存值。不重叠、不补跑迟到轮次。每家门店独立锚定编号，同店多个 SKU 合并，查询省略全局地点；只在官网实际返回其他店时共享结果，不推断同城门店都已查询。直连每轮最多并发 4 家，代理每轮最多 `min(10, 代理池容量)` 家，多余门店轮换。慢请求、代理补充、缺失门店/SKU均显示未知，不能保证每家店每轮有新结果。超过 10 秒的旧样本不会新增抢购任务。

为目标选择已添加账号，勾选“有货立即自提抢购”并设并发数和下单失败重试次数。开始监控即允许已勾选目标自动下单；未勾选只监控和通知。请提前保存账号自提偏好并预热登录；联系人可按设置复用官网已保存的信息，仍缺少官网必需项时需补充。固定单店目标只临时覆盖本次门店，不改账号已保存的偏好。

也可在“本地配置”预选多家替代门店、设置先后顺序及预约时段规则，再点击“监控预选门店，有货自动下单”。同一账号、SKU 和数量的候选池合成一项购买意图，选择已确认有货的最高优先门店，默认 1 路；不会为每家候选店各排一项购买。详见[自提偏好说明](PICKUP-PREFERENCES.md)。

同账号/SKU/门店每次补货周期最多加入一项目标，该目标可按配置串行重试；派发前持久化队列和分配记录，未知不重新武装，明确无货后再次有货才是新周期。账号忙、登录或定时任务未结束时，目标保留 FIFO 位置，其他可用账号可继续使用空闲名额；提交结果未知会阻止该账号后续自动分配。

“执行队列”默认逐个处理门店目标，也支持固定 1–10 项并发。队列内所有账号共用 10 个下单子路名额，每项目标按其自身路数预留，不能把“目标并发数 × 每目标路数”当作可突破的上限。更改执行模式或并发上限前，先暂停，等待在途任务与协调器结束，再保存并继续。暂停不会撤销已到达官网的请求。

执行队列自 0.1.8 起与后续监控库存解耦：新鲜有货信号触发排队后，即使监控明确无货、未知或样本过时，仍按 FIFO 正常下单，由官网实际结账结果决定是否成功。原“下单前检查库存样本时效”开关移除。实际失败记录真实原因，确认未提交时按目标已配置的失败重试次数执行；已有订单、提交未知或需要认证时停止重试。关闭授权或移除目标仍保留任务，恢复原授权并重新确认有货后才可执行。手动取消仍有效，历史取消不会自动复活。队列页面按最新倒序展示，实际执行保持 FIFO。重启保留未执行队列排序并清除旧库存依据；此前开启的监控自动恢复，原本运行中的队列等待新的库存确认后按原授权继续，手动暂停继续有效。已派发或中断任务不自动重放，定时任务需重新设置。主动停止监控后重启保持关闭。兼容和验证见 [监控重启恢复](MONITOR-RESTART.md)，完整队列状态见 [队列说明](QUEUE-LOGS-SESSION.md)。

监控页“最近有货”展示持久历史，含真实采样时间、SKU、门店名称与编号。连续有货及服务重启不重复记卡；只有明确新鲜无货后再次有货才产生新事件。历史记录不计入当前库存。默认展示最近三条，更多记录可展开；门店抢购参数、添加目标、代理与说明按需展开。

## 动态库存代理

展开“动态代理池”，配置星月/XY、大漠/DM或通用提取接口，可填白名单接口、用户名/密码和租期。默认容量 10。私有字段加密保存，读取只显示已配置标记，留空保持旧值。未启用不提取付费代理；不会自动复制参考项目付费凭据。

可派发连接轮转复用，后台每批不超过 `ceil(容量/5)`，提取请求至少间隔 1 秒，到期前 10 秒准备替换。失败、403/429/541、挑战和非JSON丢弃当前连接再补充；无可派发代理显示未知，不回退到账号连接。连接健康不等于实际库存成功。池有单一进程所有者，运行监控时读取门店通过私有共享查询通道复用该池，无需先停止监控；独立单次库存检查仍需避免另开池。XY 自动白名单省略来源 IP，由供应商识别真实出口。

## 并发自提和时段规则

人工、定时和监控自提默认 1 路，可配 1–10。每路均按所设数量购买，可能产生多笔待付款订单。送货和自提前准备继续原单任务流程。

“下单失败重试次数”默认 0，可配 0–10 次额外重试。设置 2 表示首次失败后最多再试 2 次，总共最多 3 轮。每轮完全结束后才开始下一轮，账号仍由同一任务占用；手动、定时送货/自提和监控触发均使用相同规则。每轮按所配自提并发路数执行，任一路已产生订单就不再启动新一轮。提前准备不启用失败重试。

只有确认尚未提交订单的失败才重试。已有待付款订单、提交标志、落盘的未知提交、取消或需要人工处理的认证会停止重试；不会因重试次数未用完而再次提交。任务阶段和日志显示本次下单及重试进度，定时任务会冻结设定时的重试次数。

多路或可能重叠的并发结账由父任务保留账号锁并先核对一次登录，为各子进程创建独立认证/配置快照。不复制浏览器资料、准备缓存和旧订单标记，子进程不能开启浏览器登录，Cookie不回写原账号。每路独立展示结果、付款码或提交未知；取消和父进程退出终止其子进程，不重试未知提交。队列逐个执行且目标仅 1 路时，则复用原账号的正常结账链路，可处理官网重新认证。

商城登录成功不保证结账页免认证。若 Apple 要求本次结账重新认证，并发结果会明确提示使用单路下单完成认证，而不是要求反复预热；这类错误不自动重试。单路沿用原有账号认证流程。

工作台支持“官网登录恢复（保留账号）”，手机 PWA 可在当前任务预览并操作本机为该账号打开的官方浏览器窗口。“空闲预热”在账号连续 10 分钟没有执行下单操作后运行“预热登录（不加购）”；手动、定时和监控下单均重置计时，实际下单优先停止预热。未来尚未触发的定时任务不阻止预热；未知订单结果、认证与访问限制仍待处理。详见 [会话恢复与远程窗口](QUEUE-LOGS-SESSION.md)。

Apple 服务端购物袋可能仍共享，因此并发尝试数不代表成功订单数。每路复核商品、数量、门店、金额和支付宝；不一致停止。门店同时匹配名称与接口编号。需要预约时使用官网当前签名，按最早、最晚或设定时间范围选择有效、未禁用且无限制的完整时段；不能复用旧签名猜测时段。多店模式只在明确未提交且官网证明门店或时段不可用时尝试下一预选门店，未知失败不盲目换店。

## 数据与验证

代理配置/租约/用量、VAPID私钥、推送订阅和提醒状态采用 AES-GCM。Windows主密钥由当前用户DPAPI保护，其他平台密钥文件仅限本用户。备份整个数据目录及 `settings/.private-state.key`；Windows恢复还需原用户DPAPI能力。原有账号和浏览器资料沿用已有存储。

验证明细见 [验证记录](MONITOR-PWA-VERIFICATION.md)。离线测试、实际库存读取、真实下单与实体手机通知是不同证据，分别列出。

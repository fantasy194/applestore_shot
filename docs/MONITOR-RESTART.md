# 监控随应用重启恢复

自动监控的运行开关由共享任务引擎持久化，本地 Web 和桌面程序采用同一规则。关闭浏览器页面不影响服务端监控；关闭或重启本地服务后，原先开启的监控在服务就绪后自动恢复一次。

## 使用行为

1. 保存目标、账号及“有货立即自提抢购”授权，点击“保存并开始监控”。此次开启同时记录重启后恢复的意图。
2. 应用退出或崩溃后重新启动，监控重新读取已保存的加密配置并发起新的匿名库存查询。保持原账号、SKU、数量、候选门店、并发及重试限制；未勾选自动抢购的目标继续只监控和通知。
3. 此前运行中的队列恢复原运行意图，但旧信号不能直接触发购买，未执行项需重新确认一次新鲜且仍获授权的有货结果；此后监控无货、未知或样本变旧不再拦截该项正常派发。用户手动暂停队列后，监控仍可恢复并显示库存，队列继续等待本人恢复。
4. 点击“停止监控”会先持久化关闭意图，再结束本次 worker；以后重启保持关闭。仅保存配置或检查一次不会开启恢复。

监控启动失败显示已有的任务失败状态和原因，并记录安全日志；不在后台循环重新登录或无限重启 worker。修正配置后可主动重新开启，也可直接点击“停止监控”关闭重启恢复，无需先把失败任务重新启动。

## 队列与订单边界

- 未执行任务保留原顺序、原账号和冻结的门店规则，重启后重新等待当前授权及一次新鲜有货信号；确认后按队列正常执行。
- 已取消任务不自动恢复。重复库存样本与重启沿用持久化的购买意图去重状态。
- 已派发或在途购买在启动恢复时标记中断，相关账号等待官网订单核对；提交未知继续阻止该账号自动派发。
- 定时任务、人工操作和自提前准备不因监控恢复而重放。待付款不是付款完成。
- 手动暂停或取消整个队列的选择会跨重启保留；正常退出为了清理而暂停队列，不覆盖用户原先的运行意图。

## 数据与旧版本兼容

`settings/monitor_runtime.json` 只保存版本与监控是否开启，不保存账号信息、库存、代理凭据或联系人。库存目标和代理配置继续由现有加密存储管理。每个引擎实例只领取一次启动恢复，避免初始化或重复调用产生多个监控 worker。

旧版本没有运行标记时，仅最新且明确尚未结束的本地监控任务可迁移为开启；已取消、失败或历史中断任务不用于猜测开启状态。同一秒的最新历史包含结束证据时保持关闭，不用随机任务 ID 猜测操作先后。没有可靠的开启证据时，点击一次“保存并开始监控”即可记录后续恢复意图。旧队列按已经保存的暂停状态迁移，已经暂停的队列需要手动继续。

## 验证

独立暂存源码的共享引擎回归 **128 项全部通过**，其中监控恢复专项 **7 项**通过。进程回归覆盖正常退出、崩溃、队列暂停、取消整个队列、在途 / 未知订单、已取消单项和主动停止共 **7 种场景、14 个独立应用子进程**。子进程实际启动 Python worker，通过私有 IPC 读取重新保存的加密库存配置；新的库存门槛打开之前，下单计数始终为零。失败后主动关闭、取消旧历史不影响新监控、旧版同秒启停的保守迁移另有覆盖。

前端 **175 项**回归全部通过，包含监控失败后无需重启任务即可关闭恢复的入口。Web 构建、桌面 Rust 1.90 编译检查和 Python **696 项**回归（695 通过、1 跳过）也通过，具体命令及工具链范围见[交互复审记录](INTERACTION-REFINEMENT.md)。

证据位于本地 `artifacts/followup-staged/artifacts/` 的检查日志。隔离目录、合成账号、库存与订单 fixture 不证明真实 Apple 库存、登录、订单创建或支付，本次没有重启用户现有服务。

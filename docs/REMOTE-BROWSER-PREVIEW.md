# 官网实时远程画面

手机、浏览器和桌面的“Apple 官网窗口”共用同一预览组件、页面归属和输入检查。worker 使用当前页面的 CDP `Page.startScreencast` 推送变化画面；Web / PWA 经认证 WebSocket 接收，不再重复请求截图。桌面通过私有桥接长轮询同一增量事件，使用相同的心跳、连接与页面状态判断；静态画面不重复传送。

静止页面由独立心跳确认仍连接，心跳不携带重复图片，也不触发重复解码。操作是否可用取决于本机收到最近状态的单调时钟、当前 CDP 连接和页面标识；服务器与手机时钟偏差、画面静止均不再导致五秒后失效。超过五秒未收到状态或连接断开时暂停操作；实时连接允许最长十五秒的网络停顿再重连，避免慢代理反复打断连接。聚焦本地输入框或重新回到页面时保留健康连接；恢复已失效连接采用有界退避。重连读取当前状态，不重放输入和登录操作。

新帧解码完成后再替换显示。临时连接失败保留上一帧及输入草稿；切换页面立即移除旧页面画面，等待新页面的有效帧。运行中和等待人工操作继续共用一个预览；任务结束、窗口结束或切换账号 / 任务会清除原画面及未发送输入。迟到请求、解码和连接回调不能覆盖新页面或新任务。

点击和滚动绑定实际显示帧的序号、页面标识与原始尺寸，按下到释放之间冻结显示画面。输入仍由服务端核对账号、任务、页面和连接，不依赖客户端时间或绕过失效检查。

WebSocket 建立前通过现有认证请求 `POST /api/browser-stream-session` 设置 HttpOnly 会话 Cookie，随后连接 `/api/browser-stream?account_id=…&task_id=…`；URL 不携带访问密码或长期令牌。通道保留来源、账号和任务校验，丢弃过大或畸形消息，并在组件卸载时清理重连、认证请求及事件监听。服务端每秒最多发送十次最新状态，避免动画画面积压；WebSocket 连续失败后自动改为经同一认证接口读取相同 `events` 增量事件，静止页面仍只发送心跳，不重新截图。HTTP 降级首读从零开始取得当前帧，卸载时中止在途读取。

“使用现有凭证登录”按钮发送当前任务内的 `signin` 操作，调用共用官网登录助手；不从前端重新传送密码、不另起任务。新增账号、官网登录恢复和预热使用相同的账号核对、鼠标聚焦、100–200ms 随机键盘输入及登录提交规则。缺少可用密码时显示正常手动输入提示；验证码和官网安全验证仍由用户完成。详细边界见 [官网登录助手](BROWSER-LOGIN-AUTOFILL.md)。

导航造成短暂 CDP 页面竞争时保留十秒恢复机会，立即作废旧页面画面与输入；持续失败或浏览器断开后才结束预览。输入在执行前因页面变化等原因被拒绝时明确提示“未执行”；已开始输入或点击后发生异常，以及响应丢失时显示“操作结果未确认”，要求先查看官网，避免把可能已执行的操作当成未送达而重复发送。

输入草稿只在内存中暂存，发送后清空，不写入浏览器存储或任务日志。点击画面聚焦后可使用“空格”按钮，或者发送含空格及纯空格的文本，不裁剪输入。

## 验证

`tests/ui/remote-browser.spec.ts` 使用合成画面与桥接 fixture，验证连续推送、静止心跳、时钟偏差、断线恢复、慢请求、迟到解码、坐标映射、页面 / 任务切换以及手机布局。`tests/ui/browser-stream.spec.ts` 验证认证会话、WebSocket 重连、健康连接聚焦保留、代理拒绝升级时的增量 HTTP 降级、过大消息拒绝及清理竞态。两组测试不访问 Apple、不使用真实凭证、不创建订单。

`scripts/verify-browser-stream-fixture.py` 使用本地 Chrome / CDP 与合成官网页面，验证静止六秒后继续操作、CDP 推帧、输入、超过五秒的逐字输入期间仍持续心跳、同 URL 刷新拒绝旧输入及关闭窗口清理等七项。`docker/verify_browser.py` 在 jlesage 浏览器容器内覆盖相同的静止心跳与推帧检查，并检查 GUI、沙箱、输入和账号资料隔离。这些是本地真实浏览器与容器证据，仍不代表真实 Apple 登录。

生产构建及双架构发布沿用 [GHCR 工作流](../.github/workflows/ghcr.yml)。更新保留 `/data` 挂载和 Web 密码；容器健康与预览回归不能作为真实 Apple 登录成功的证明。

# 登录与凭据生命周期（0.1.17）

0.1.18 补充 [已验证凭据保留与认证归属](VERIFIED-CREDENTIAL-RETENTION.md)：已被官网接受或与已确认保存记录匹配的密码，不再因后续一次认证拒绝自动删除。下文的候选密码失效须服从这一保留规则。

## 本次问题与证据

G3P 在 2026-10-25 早上出现自动维护、队列购买提示没有密码，随后普通登录成功、购买进入浏览器又中断的情况。只读核对确认这些操作处在同一 0.1.16 服务运行期间；加密保险库可用，但该账号没有可读取的密码记录。这不能说明用户没有输入密码，也不能归因为此次容器重启。08:22:38 的确有 App 密码提示，08:22:51 则是浏览器输入中断；原界面把 `manual` 暂停状态也显示成“没有可用的登录凭证”，因此该提示不能证明服务内缓存密码缺失。

源码存在几处不同的缺口：服务内缓存未携带用户的保存选择；持久保存依赖整个任务最终成功，认证成功后因库存或结账失败可能漏存；通用认证失败会被清理代码当成密码拒绝；浏览器预填或手工输入的失败也可能错误清除另一份 App 缓存密码。原日志只记录通用浏览器错误，不能确定截图中每次输入中断的底层原因。

## 同一账号的密码来源

App 密码提示和预填密码通过同一私有通道进入按账号隔离的服务内存。即使没有选择持久保存，同一服务运行期间的后续登录、维护、恢复、手动、定时和队列认证仍可复用。用户选择保存时，该选择跟随当前密码代次传给后续 worker，不进入购买参数或任务文件。

只有本次实际使用的 App 密码获得官网正向认证确认，才尝试持久保存。保存不再依赖后续有货、结账或订单创建成功。缓存、提交证明和认证证明按当前密码绑定；仅读取密码、复用健康会话、浏览器已有密码以及登录页面上的旧提示，都不能证明 App 密码已通过认证。隔离购买子任务经现有账号认证租约回报，由父账号保存。

候选密码失效必须绑定本轮实际提交且尚未被确认接受的密码。明确拒绝只清理该候选缓存，保留其他已存密码供下一任务读取；此前已验证的密码保留，不能把本轮认证失败当作密码已改变的证据。普通认证错误、验证码错误、HTTP 541、网络失败、焦点中断及另一份浏览器密码失败不清除 App 密码。迟到的旧任务结果不能清除较新输入。主动忘记密码、移除账号和服务退出仍清除相应内存状态。

保险库缺少记录与读取失败分别处理。配置或解密错误报告具体存储错误，保留密文；不会改成“没有密码”或覆盖损坏记录。当前确实没有可用密码时，在当前 App 任务提示输入；是否持久保存服从用户选择。直接向官网远程窗口发送的任意文本不自动采集为账号密码。

## 统一会话恢复

购买先接手有效自提准备或复用当前会话。首次添加、保留账号恢复、空闲维护与购买前核验共用现有账号协议：

1. 有会话时读取当前账号页；健康时不提交密码、不另开完整登录。
2. 官网本次响应实际要求认证时，沿用同一个 Session、动态登录入口和已保存设备信任，使用与首次登录一致的认证协议。
3. 没有商城会话时，使用首次完整登录流程。需要六位验证码时仍由当前 App 任务输入；是否需要验证由官网决定。
4. 本次商城交换明确返回 541，才在原账号资料内有界转交浏览器一次；不循环重发认证。已经进入 Checkout 的恢复仍属于原购买，不重新加购或重放未知提交。

普通网络超时、模型未知和任意 403 不当成重新登录的依据；真实认证拒绝保留具体原因。空闲维护不能封锁购买，历史失败不补跑。

## 浏览器输入

没有人为逐字或点击延时。输入使用捕获的原字段句柄，将存活、焦点和预期前缀检查合并为一次读取，避免每字多次重新定位以及字段消失后的自动等待。输入前因密码提示等造成的同文档字段重建，在重新核对官方页面、账号和唯一字段后最多重绑一次；输入中换文档、换字段、失焦或值异常仍立即停止，不自动续输。

App 等待用户输入密码和验证码的时间不消耗自动键入时限。输入暂停、实际缺少密码和需要验证码分别显示；输入暂停不再显示成“凭据不存在”。诊断只记录白名单阶段、原因和浏览器错误类别，不记录账号、密码、长度、页面内容或原始异常正文。

## 监控等待修复与验证边界

监控在读取配置、取消检查之后重新计算等待剩余时间；截止点已过则继续下一轮，不向 sleep 传入负数，也不补跑累积轮次。确定性测试通过配置读取延迟复现原异常，修复后监控继续运行。

回归使用合成密码、隔离账号数据和本地 Chrome 拦截页面，覆盖跨任务缓存、选择保存、认证成功后下单失败、通用认证失败保留、明确拒绝、租约归属、密码提示期间字段重建和输入中断。`node scripts/python.mjs scripts/verify-browser-input-lifecycle.py` 可复验原生表单、认证 iframe 的十二个真实 Chrome/CDP 场景，结果保存在 `artifacts/browser-input-lifecycle.json`。合成表单耗时改善不等于真实 Apple 网络耗时，也不证明官网未来不再要求认证、返回 541 或验证码；真实订单和付款分别需要现场证据。

## 共享恢复路径

只对本次实际响应的官方过期文档尝试一次恢复：HTTPS、官方 `www.apple.com.cn`、200，以及明确的 `/shop/sorry/session_expired` 或 `/cn/shop/sorry/session_expired` 路径。旧模型、手工设置的 URL、一般未知页面、登录页、网络错误、541 或明确无货不触发这条路径。

恢复保留原账号、HTTP Session、浏览器资料、购买意图、队列分配及授权范围：

1. 检查取消、当前配置、监控授权、商品数量以及所有已提交／结果未知标记。
2. 读取当前购物袋，严格确认实际 SKU、数量且没有额外商品。不加购、不修改数量。
3. 使用这次购物袋返回的动态结账操作和请求令牌，只发送一次初始化请求；异常或写结果未知不重发。
4. 清除旧门店、预约签名、联系人和 Review 就绪证明。新结账按共同流程重新核对实际门店、上海时间七天内最早有效时段、联系人、金额及支付方式。

手动、定时、自动队列、活准备接手和续期共用该恢复能力。准备续期只恢复到当前结账并返回原等待层，不嵌套新的等待、不提交订单。一个原会话只消费一次恢复预算；已失败历史不会重新入队。

不能核实购物袋、当前操作、配置或授权时，保留明确停止原因。恢复不扩大购买数量，也不把此前提交结果未知的订单变成可重试。

## 两条查询链路与两种间隔

自动监控继续使用独立匿名会话和原有代理策略，不携带账号 Cookie。账号结账准备内的门店查询复用原认证 Session，只在这次查询期间禁用环境及 Session 代理，完成或失败后恢复原传输配置，不关闭 TLS 校验。

当前 Fulfillment 明确等待选店时，按独立保存的 `prepared_inventory_interval_minutes` 执行官网提供的门店 `search`，默认五分钟、支持 1–60 整数分钟。实际周期回调与五分钟提示租约分开；设置一分钟会在一分钟触发，不会仍等待五分钟租约结束。它与购买流程共用查询参数和操作，不选店、不填写联系人、不继续结账、不提交订单，不把结果发布为自动监控到货信号。已选店或 Review 不为实验回退重填；实际购买不受这条准备查询限频限制。

查询前需要当前商品证据、当前搜索操作和令牌。官网省略商品行时，可使用本次已完成的只读购物袋核验产生的十秒内私有物证，绑定同一页面对象、同一 Session 和精确 SKU／数量；它仅用于允许查询，不能证明可提交。增量查询结果可以省略页面名称，但必须属于本次 Fulfillment 操作；不伪造原始响应，不继承旧有货结果。明确无货保留部分准备，未知、网络和限制错误不重试。

这是一条实验性维护路径。查询是否延长服务器结账寿命尚未现场证实，日志分别记录 `prepared_inventory_refresh` 和 `checkout_recovery`，便于比较是否仍发生官网过期。明确过期时仍使用前述恢复路径。

工作台提供“空闲预热间隔”和“准备内库存刷新间隔”两个独立设置，均默认五分钟、可保存 1–60 整数分钟。前者控制何时启动维护，后者控制本轮准备内的查询周期；新准备读取已保存值，已有任务使用派发时冻结值。Rust 调度和 Python 失败等待使用同一个派发时配置；旧失败记录不能把新设置继续锁成十分钟。旧固定十分钟迁移到新默认，新版本明确保存的十分钟及已有合法自定义值保留。修改不取消当前准备／购买，不改变五分钟提示租约，也不改变自动监控的检测频率。

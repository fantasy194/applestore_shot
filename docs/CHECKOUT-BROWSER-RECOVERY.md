# 结账认证与官网浏览器接管（0.1.12）

## 现场证据与问题范围

2026-10-24 香港时间，G3P 在同一 0.1.10 容器运行期间出现：19:52 后台登录维护成功；19:56 实际购买的 Apple 账号认证成功，但商城 authx 返回 541；随后的手动“官网登录恢复（保留账号）”成功，再次购买推进到结账，最终无可用自提库存或时段。相关购买均未提交订单。容器自 18:59 起未重建，账号数据卷、浏览器目录及权限未变化。这些证据不支持“此次发布丢失会话”的解释，也不能证明 Apple 返回 541 的内部原因或固定会话有效期。

源码中的缺口是：购买前账号读取成功即跳过浏览器恢复，结账另行要求认证时使用 HTTP 协议；该认证的 authx 返回 541 后直接终止，且失败清理会删除部分商城认证 Cookie。手动浏览器恢复走官网脚本和原浏览器资料，再导入会话，两者的后续处理不同。账号页可读、维护 healthy、Cookie 未过期均不保证下一次结账交换被官网接受。

## 统一恢复约定

正常结账继续使用原 HTTP Session。仅当本次结账认证的商城交换明确返回 541，且当前购买尚未提交时，允许原认证范围内进行一次官网浏览器接管。它使用原账号 profile、同一登录助手和本次动态 signIn 入口；官网脚本负责认证、信任及实际 checkout 跳转。不得猜测或重发旧 authx，也不得从购物袋重新启动一次购买。

浏览器保留自身的校验和设备信任，将当前购买的商城与购物袋上下文带入本次登录。恢复结果必须来自官网实际返回的结算文档；原 Session 和 Checkout 对象接收当前 Cookie、浏览器 UA、页面模型及令牌。继续前检查账号、原 SKU / 数量、有效结算步骤，并沿用后续门店、时段、联系人、金额及支付方式复核。恢复失败或再次被官网拒绝时结束本次尝试，不循环认证。

同一次账号身份核验通过后，将浏览器的新会话和设备信任保存到原账号目录；并发子路也由父账号保存，不只更新临时子任务。后续购买可读取该会话，错账号或核验失败不覆盖原文件。

541 不等于密码拒绝。保留当前响应已经更新后的 Cookie 状态，不批量清空商城会话，也不从旧快照恢复服务器已删除或过期的 Cookie。原浏览器资料与保存凭据仍按既有规则保留；明确的账号密码拒绝沿用凭据失效处理。

## 隔离子任务与保密

手动、定时、队列及并发子路都调用同一结账恢复接口。隔离子路通过现有账号认证租约请求父账号浏览器，不能创建替代 profile 或争抢父账号资料。请求、结果、验证码和取消绑定账号、子任务、提示及租约，单次租约只允许一次浏览器恢复。

Cookie 和结算模型仅走私有传输；不得写入公开事件、任务摘要、日志或队列清单。较大对象使用所属任务内的受校验私有临时文件，用完清理。未知提交、已有订单和历史失败不因恢复而重放。

## 验证边界

0.1.12 本地验收：Worker 全套 902 项通过（3 项跳过）；新增真实 Chrome/CDP 合成结账 6 场景和原官网恢复 20 场景通过。覆盖保存凭据、当前任务验证码、错账号、密码拒绝、商城再次 541、实际 POST 结算文档、父账号持久化及身份核验后的 Cookie 更新；跨层回归确认最终保存不会把新会话回滚。串行与真实子进程的认证错误保持一致，子进程发出私有请求后立即退出也会清理已登记文件。

单元测试、真实子进程 IPC 和本地 Chrome 合成页面分别验证业务分支、归属与保密、动态登录与官网跳转模拟。它们不能证明真实 Apple 会接受恢复，也不能保证消除未来 541。G3P 真实验证仅在必要时按用户授权少量执行，间隔按分钟计，不连续重试；已有现场记录可用于诊断时不额外制造订单。

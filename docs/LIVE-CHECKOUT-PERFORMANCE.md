# 0.1.20 活结账、准备续期与自提提速

## 目标和既有样本

统一手动、定时和监控购买，尽量把库存出现后的工作缩短为接手、当前官网复核和最终提交。指标是“首次发现库存至提交请求发出”；收到订单号、加载二维码和付款另行统计。

2026-10-25 的 #14 在 22:25:14 发现库存，约 0.3 秒完成入队与派发，15.9 秒才开始实际购买，约 42 秒后选店返回不可用，未提交订单。账户读取及两段认证的已识别请求累计 21.71 秒，读取结算页 6.42 秒。复核全部请求日志（包含动态跳转阶段）共 23 个请求、累计 38.83 秒；此前只聚合静态阶段所得的 21 个请求、34.27 秒不是完整总数。该样本属于 0.1.18，不是本版下单验收。

主要优化是提高有效准备命中率、保持原 Session/Checkout、减少重复身份核验。没有通过增加同账号路数、提高失败重试次数或跳过最终核对实现提速。

## 准备范围

空闲自提准备优先参考当前运行监控中明确自动购买的账号、SKU、数量与门店。一次只准备一组相同商品和数量；优先账号预设匹配组，否则取稳定首组。账号原门店顺序只提供排序与已有查询信息，不排除独立监控已明确授权的其他门店。

Rust 提供规划提示，Python 在实际开始、续期和接手时重新读取服务器当前加密监控设置。目标撤销、账号/SKU/数量/门店变化或不相容规则不能沿用原授权。联系人与证件规则仍取账号配置，不公开证件末四位；原配置文件不被临时范围覆盖。

准备范围可以大于本次购买范围，但两者不混淆：

- 手动、定时没有显式门店覆盖时仍按账号原配置，不能自动使用整个监控范围。
- 队列分配明确单店时只执行该店，即使原账号或准备含有优先门店池。
- 每份购买分配保留自己的购买目标、数量、任务、队列 ID 和分配代次；共享准备不增加购买次数。

## 五分钟租约与原会话

每次准备提示仍有五分钟期限。到期撤销旧提示，在同一 worker、HTTP Session 和 Checkout 内只读重新获取当前结账，核对配置、当前授权及商品后发布新提示。旧提示不能认领新租约；取消、重启和结束准备均不会恢复购买。

续期不重复加购、提交表单或创建订单。Review 就绪必须重新证明当前商品、门店、有效预约、联系人、同一金额、支付宝及官网允许继续；缺少依据时显示部分准备，不能继承旧的可提交结论。官网真实要求认证、返回未知步骤或无法核验时结束本次保留；实际购买仍走同一自动恢复入口，维护状态不封锁购买。

## 单店失败后的续用

活 Checkout 仅保留在当前账号进程内，不从磁盘恢复。下一目标只有在账号、SKU、数量、账号配置及有效期匹配时才能消费。

允许续用的失败严格限于：明确的门店/时段不可用，尚未提交订单、尚未尝试继续 Fulfillment、当前仍在 Fulfillment，且没有认证失败。网络错误、继续请求结果未知、已有订单和未知提交都结束此续用路径。

下一份新授权分配通过正常购买入口消费同一 Session/Checkout，重新读取当前结算并核对商品；新目标使用新的门店、联系人和时段证明，不沿用异店签名。省去重新读取购物袋、菜单核验和重新发起 checkout 的路径。

若首项来自准备接手，先发送首项独立的失败 ACK，再由同一 worker 进入队列执行器、发出 `queue_ready`，之后才允许下一新分配。未发出 ready 的旧 worker 仍须退出后再另开执行器。迟到或重复 ACK 不能改变下一项；历史失败不会补跑。

配置的额外重试仍由统一重试器负责。发生新一轮重试后，原准备 Session 先交出持久化所有权，不能在退出时把旧 Cookie 覆盖到新会话，也不能在后轮失败后重新保留首轮 Checkout。

## 避免重复账户认证

只有实际官网账户响应精确确认当前 Apple ID 后，才能签发短期身份证明。证明使用本次 Engine 运行的随机密钥，绑定账号 UUID、账号标识摘要、auth/profile 路径、精确 Cookie、UA 和墙钟/单调时钟的五分钟期限。

当前快照完全匹配时，购买可省去独立账户页请求；缺失、过期、被拒绝、Cookie/UA/路径变化或服务重启换密钥时仍核验。正常同一 Session 的官方响应可以更新 Cookie 摘要，但不延长最初期限。公共 Session、旧 Session 或旧代次不能撤销或覆盖另一份新证明。

密钥只经 worker 私有请求头部传递，不进入业务 params、快照、日志或持久文件。证明文件不保存密码或 Cookie 明文；该密钥与持久密码保险库主密钥无关。账号身份证明只省略重复身份读取，不表示官网结账认证或库存已经有效。

## 手动先填写、等待库存再提交

保留原有“提前准备自提（不下单）”入口。官网已经开放联系人或地址步骤时，使用同一表单流程自动填写；只有本次官方继续操作被接受后才记录受理证明。若响应超时，通过同一 Checkout 的当前只读响应确认步骤已推进后，给本次实际提交的字段补记受理证明，不重发该 POST。

已受理信息保留在同一 Session；库存恢复后继续本次结账，并在最终 Review 统一核对固定门店、候选门店和自动队列的联系人。官网使用掩码时，只能与本会话实际受理的证明核对，不能把本地配置或掩码当成完整联系人发送。

官网若只允许停在无货的 Fulfillment，则保留这一步及本地配置；不猜造联系人入口，不伪造库存或预约签名。完整 Review 与部分准备分别展示，只有真实密码、验证码或确认提示才显示需要操作；自动等待库存不显示人工待办。

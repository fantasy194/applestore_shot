# 活自提准备接手

自动自提准备通过 `prepared_purchase` 私有提示保留原 worker、Session 和 Checkout。磁盘上的 `prepared_checkout.json` 仍只是检查点，不恢复活任务，也不会在重启后自动提交。

准备记录包含账号归属、SKU、数量、自提方式、配置指纹、配置文件 SHA256、授权门店、准备时间和单次最长五分钟租约。手动购买、定时触发及队列派发共用 Engine 接手入口：SKU、数量、配置、授权和单路条件匹配后，向原提示发送一次带来源的 `prepared_claim`，原任务提升为真实购买，不取消原 worker，不建立第二份购物袋。普通提示回复接口不接受该提示。0.1.20 可在原 worker/Session 内只读核验、撤销旧提示并发出新租约；过期提示不能认领新租约。

Worker 接手后仍须用当次官网响应核对商品、金额、门店、时段、联系人及配置。准备不等于库存预留或下单授权扩大；不匹配或过期时取消准备让路，执行原普通购买链路。未知提交始终阻止接手和自动重放。

定时任务在触发时间才尝试接手，原定时任务记录指向实际准备任务，跟随其最终结果；取消来源任务也取消原准备。不会在准备被消费时提前把定时购买标为成功。两条记录共享一次实际购买。

队列在持久化队列项和分配代次后消费准备。原任务先绑定该单项队列身份，只接受对应的开始和完成 ACK。0.1.20 若该项明确未提交、仅门店无货且仍处 Fulfillment，可先终结其失败结果，再进入普通队列执行器并发送 `queue_ready`，接收下一份新授权的 `queue_add`；同一活 Checkout 始终串行，旧项迟到 ACK 不能完成新分配。成功、未知提交、认证失败、网络错误及已尝试继续步骤均不能走这条续用路径。

准备租约到期不代表购买失败。正常续期只读，不重复加购、填写表单或下单。0.1.21 在当前官网明确返回登录入口时，可沿原 Session 和本次动态入口自动恢复，整个活准备生命周期最多一次；旧认证必须已成功且新关键认证范围不同，不能因布局或追踪参数变化重试。恢复前后重新检查取消、配置、授权与商品；未知页面不触发猜测登录。仍无法核验时结束本次保留，后续购买使用统一恢复入口。真实购买重新计算空闲时间。已准备且只等待接手的账号不占用其他账号开始预热的全局窗口。失败历史不会因此复活，应用重启也不恢复在途准备。

监控准备可以覆盖当前明确授权的同账号、同 SKU、同数量门店，但共享的是准备状态，购买意图及数量保持独立。普通手动、定时没有显式门店覆盖时仍按账号保存的原范围；准备覆盖范围不能反过来扩大本次购买。详情及验证边界见 [活结账优化](LIVE-CHECKOUT-PERFORMANCE.md)。

Engine 回归使用真实子进程，比较准备前与接手后实际 Python PID，覆盖手动、定时接手、SKU / 数量 / 门店 / 路数不匹配、配置变化、过期及普通回复绕过保护。该证据验证本地协调，不代表真实 Apple 库存、订单或付款成功。

# 购买前自动会话核验（0.1.9）

## 当前流程

空闲维护用浏览器主动刷新账号会话；购买优先走现有 HTTP 会话的一次只读账号核验，确认实际账号后立即进入原结账，不为有效会话启动浏览器。其他任务的 `healthy` 只是维护结果，不替代本次只读核验。

如果现有会话无法核验，当前任务使用原账号浏览器和已保存凭据自动完成一次官网恢复，再继续原购买流程。维护冷却记录、旧 `requires_login` 状态以及历史 `.authx-541` 标记不再直接阻止这次恢复。只有本次核验成功才记录购买依据；失败仍报告官网或网络的实际原因。

登录、手动恢复、空闲维护及购买认证共用登录助手。正常账号、密码和信任步骤自动完成，六位验证码通过当前任务输入框交给用户；输入后继续同一浏览器、同一任务，等待验证码不消耗自动登录处理时间。验证码不持久化，取消立即结束等待。保存凭据缺失或错误、无法识别的安全挑战仍如实报告，不能凭空补出密码或绕过官网挑战。

空闲十分钟是后台调度间隔，失败后下一个空闲周期继续尝试；不再因旧的一小时/半小时冷却永久要求用户先点恢复。运行或等待验证码的任务不重复派发，购买仍优先于空闲维护。

## 购买与重试范围

单个购买及同一队列波次共享已验证会话，核验位于购物袋写入和并发快照之前。并发子路不单独启动浏览器；官网若在结账阶段再次要求认证，保留原 Checkout 和 Session，使用父账号提供的凭据继续该入口，并串行协调验证码。长队列超过本地五分钟复用窗口时，等待在途子路结束后再次核验。本地窗口不代表 Apple 的会话有效期保证，账号页核验也不等于结账免认证。见[购买流程一致性](PURCHASE-FLOW-PARITY.md)。

当前官网的 403、429、541 或网络失败不会触发认证/购物袋/订单无限循环。自动恢复发生在购买写请求之前，不自动重放已经发出的订单；未知提交仍阻止该账号继续购买。SKU、数量、金额、门店、时段、联系人复核和用户设置的失败重试次数保留。

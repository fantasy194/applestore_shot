## 界面行为

| 范围       | 原问题                                               | 调整                                                                                   |
| ---------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 下单进度   | 当前步骤藏在工作台底部，切换页面后难以关注           | 顶部固定显示账号、当前步骤、简短阶段及查看任务入口；多个下单任务可切换，运行中可取消   |
| 执行队列   | 每个任务的详情、日志入口占据大量高度，失败原因不突出 | 商品、门店、账号数量和当前步骤直接显示；时间及来源按需展开，详情与日志收为紧凑操作     |
| 级别与状态 | 普通记录、失败、待付款难以区分                       | 运行蓝、成功绿、待付款琥珀、失败及提交未知红、取消灰；同时保留明确的状态文字           |
| 运行日志   | 一条记录多层堆叠，时间不明显，重复元信息干扰扫读     | 桌面 34px 单行，手机约 52px 双行；毫秒时间、彩色级别及正文优先，按日期分组             |
| 完整日志   | 长错误信息与辅助字段需要保留                         | 整行点按或 Enter / Space 展开完整正文、账号、分类、事件及 JSON；增量更新保留已展开状态 |
| 展开器     | 字符箭头与图标混用，展开时改变列归属                 | 统一 `DisclosureSummary` 的 SVG 箭头；原生键盘语义、焦点及表单值保留，内容沿纵向展开   |
| 监控设置   | 展开时标题从右侧跳到整行，删除按钮落在左列中央       | 标题始终靠右且保持同一列，删除按钮固定靠右，提供至少 44px 触摸区域                     |

320px 窄屏下，步骤标签保持单行。队列辅助日志入口在最窄布局使用图标，保留可访问名称和提示；查看订单、付款及提交未知的处理入口始终可读。减少动态效果时，关闭箭头及展开内容动画。

## 步骤与订单证据

- 进度栏直接使用工作区已有摘要，不增加任务轮询或提前读取全量日志。`search` 等已知步骤翻译为可读文字；未知阶段不推测已完成步骤或百分比。
- Web 摘要只补充有界的待付款、未知订单号码及缺少号码的状态标记，不传输支付链接、联系人或原始订单详情。多账号尚未启用时，可以直接只读查看已有任务；不会因此发起登录或新下单。
- 待付款订单仍显示待付款；提交未知优先显示核对提醒。官网订单查询只有同时匹配原账号、订单号及已核实状态后，才能消除旧待付款提示。
- 队列每条任务展示自己的步骤。Rust 仅接受匹配账号、协调任务、队列项及分配代次的 `stage` 事件，且只更新执行中任务的说明。过期事件不能覆盖取消、失败或订单结果，内容长度有界。
- 队列 FIFO、授权范围、重试、提交未知停止规则及日志过滤、分页、导出保持原有语义。

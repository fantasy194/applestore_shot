## 步骤与订单证据

- 进度栏直接使用工作区已有摘要，不增加任务轮询或提前读取全量日志。`search` 等已知步骤翻译为可读文字；未知阶段不推测已完成步骤或百分比。
- Web 摘要只补充有界的待付款、未知订单号码及缺少号码的状态标记，不传输支付链接、联系人或原始订单详情。多账号尚未启用时，可以直接只读查看已有任务；不会因此发起登录或新下单。
- 待付款订单仍显示待付款；提交未知优先显示核对提醒。官网订单查询只有同时匹配原账号、订单号及已核实状态后，才能消除旧待付款提示。
- 队列每条任务展示自己的步骤。Rust 仅接受匹配账号、协调任务、队列项及分配代次的 `stage` 事件，且只更新执行中任务的说明。过期事件不能覆盖取消、失败或订单结果，内容长度有界。
- 队列 FIFO、授权范围、重试、提交未知停止规则及日志过滤、分页、导出保持原有语义。

## 入队时间、方式和购买草稿复审

### 时间优先的任务行

桌面使用左侧时间列，手机将时间块放到商品上方。入队时间的时分秒是主信息，日期与毫秒保持可读但降低视觉权重。下方显示“发现有货”“开始下单”“收到订单号”，依次区分监控采样、真正开始执行及官网订单证据。

- 新任务分别持久化实际入队时间与首次库存采样时间；后续监控刷新不改变首次发现时间或 FIFO 排序。
- 开始时间只接受当前账号、任务、队列项及分配代次的执行 ACK，收到订单号时间只接受有实际订单号码的待付款结果，重复事件不改写首次时间。
- 旧任务保留原入队时间兼容读取；缺少首次库存时间时明确显示“发现有货时间未记录”。不把旧的当前库存刷新时间补成历史事实。
- 页面保留完整日期、时分秒和毫秒的可访问文本，跨日时间有自己的日期。

### 按账号选择入队方式

执行队列新增“入队方式 · 按账号设置”，与全局顺序 / 并发执行设置分开。展开后读取所选账号的完整本地自提配置：

- **预选多店，按顺序择一（默认）**：同账号、商品和数量组成一次购买意图，从已授权且新鲜有货的预选门店按顺序选择。
- **各监控门店分别入队（兼容）**：每个授权目标各自入队，可能分别产生订单。

新增空自提配置默认预选多店；已有固定单店配置继续保留。此入口复用账号的本地自提方式，因此同步影响同账号手动和定时自提。切回固定方式时仍保留预选门店顺序，作为之后切回多店的备份，不扩大固定模式的授权范围。

保存前再次读取并比较完整自提配置；发现其他页面已修改时重新载入，要求核对后再保存。读取失败、账号正忙或尚无有效门店时禁止保存。切换账号后，旧请求的迟到结果不会覆盖新账号；保存期间锁定账号选择。

“候选门店模式已关闭”的意思是：该任务入队时采用多店规则，此后账号被改成固定单店模式。任务继续保留原位置和原规则。界面现改为“等待恢复配置”，明确提示恢复原方式、原授权及新鲜库存；若要改规则，取消旧任务后按新方式入队。提供原账号的“查看自提配置”入口，不自动转换或恢复已取消任务。

### 紧凑进度栏与浏览器持久化

桌面进度栏将状态、原因、步骤和操作放在同一排；失败时展示本任务返回的实际原因，长原因仍可完整查看。手机原因最多两行。五个步骤采用已完成绿、当前蓝、失败红、未到达灰；阶段证据从共享引擎的有界摘要读取，认证失败及迟到的旧队列事件不能新增绿色完成标记。只有实际返回的订单号才能证明提交已完成，待付款不显示已支付。

购买商品与“按目标总数量更新”的 SKU、数量按账号存入浏览器 `localStorage`。仅保存版本、SKU 和 1–999 的整数数量，不存账号信息、联系人、凭据或订单。有效浏览器选择优先于后续任务摘要，任务结束、切页、刷新和账号往返后保留。尚未编辑且没有缓存时仍跟随账号的已保存购买预设，包括晚到的配置；存储不可用或数据损坏时使用可用的内存值和预设。

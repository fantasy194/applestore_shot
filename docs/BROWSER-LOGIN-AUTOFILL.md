# 官网浏览器自动填写

首次添加时选择的“官网浏览器登录”、原账号“官网登录恢复（保留账号）”和空闲预热使用同一官网页面助手。默认新增的旧 HTTP 登录入口保留；此助手不改写 SRP，也不绕过官网登录或商城交换。

## 自动处理的步骤

- 在当前账号任务的官方商城登录页面及官方认证 iframe 中，识别明确的账号、密码输入和对应“继续 / 登录”按钮。
- 核对账号与当前所选账号一致，使用鼠标点击聚焦、键盘全选 / 删除，逐字键入账号与可用密码；每字延迟随机为 20–99 ms。按钮使用正常鼠标点击，不直接赋值、不调用 `fill()` / `insert_text()` 或合成 DOM 事件。
- 已填写的账号、密码可以直接继续。密码来自当前任务内存、当前系统支持的凭据保险库或浏览器已填写的当前账号表单；手动可见登录缺少密码时，沿用应用密码提示，是否保存仍服从用户选择。密码只留在内存，遵守原系统保险库存储规则。
- 明确的官网“信任此浏览器”步骤沿用已有授权处理；随后仍等待认证与商城交换结束，核验官网实际账号，成功后才保存会话。

兼容语义字段和常见字段 ID 只是定位规则，没有把合成表单当作 Apple 现场 DOM 已核实。找不到唯一明确字段或按钮时保留人工处理，不猜测任意页面上的输入用途。非美式键盘字符的底层事件由 Chromium 决定，不能宣称每个 Unicode 字符都有同一组物理按键事件。

## 人工与失败处理

Apple 设备 / 短信验证码由本人完成；图形验证码、设备确认或未识别安全挑战同样交给人工。可见恢复窗口继续等待用户，后台无头任务停止并提示打开官网恢复，不自动获取验证码或切换验证方式。

每个账号和密码步骤在一次助手任务中最多提交一次，即使 iframe 被替换或响应不明也不重交。错误密码和认证拒绝立即停止，保留账号、原密码、Cookie、信任和浏览器资料。403 / 429 / 541 及已有冷却 / 541 标记继续阻止后台重复请求；本次后台限制不会被迟到的普通认证成功或账户页响应清除。可见人工恢复只允许官方账户页成功响应解除对应等待，最终仍核对实际账号。

输入期间逐字检查任务取消、页面 / iframe 导航（包括同 URL 重载）、原字段身份、焦点和当前输入前缀；变化时立即停止剩余输入，避免把密码后半段发送到新页面。诊断只含阶段和公开错误码，不含账号、密码、验证码或原始 Playwright 异常正文。

只读维护保留原短等待，明确进入登录页面后最多再给自动操作一分钟。后台仍禁止旧 HTTP/SRP 登录入口；浏览器密码读取使用单独能力，不能借此放开嵌套结账的旧协议自动认证。

## Docker

两种空闲预热继续使用 `--headless=new`，无需 `DISPLAY`。有可用密码或当前账号的浏览器预填密码时，普通官网登录可自动继续；缺少密码或遇到验证码时提示人工。Linux 容器仍没有新增明文密码存储，也没有复制 Windows 凭据；因此不能保证容器重启后总有密码可用。人工官网恢复保留原 Xvfb 和预览入口。

## 验证边界

单元回归覆盖字段与账号绑定、每阶段只提交一次、已填写密码、密码读取期间导航、同 URL 重载、字段替换、焦点干预和取消。

`scripts/verify-browser-autofill-fixture.py` 使用真实 Chrome/CDP、隔离临时资料和合成官方 iframe 表单，拦截全部页面请求、禁用外部 DNS 和 Python HTTP。验证可见分支及无头维护自动填写、真实键盘 / 鼠标事件、验证码不自动输入、错误密码不重试，以及中途导航不继续输入。过期账户页跳转以两次真实、受拦截导航模拟，身份导入使用合成核验，测试可见分支额外强制无头以避免弹窗；不能据此证明真实 Apple 登录成功、541 已解决或与真人无法区分。安全结果写入本地 `artifacts/browser-autofill-fixture.json`。

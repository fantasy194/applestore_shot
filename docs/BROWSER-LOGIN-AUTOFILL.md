# 官网浏览器自动填写

首次添加时选择的“官网浏览器登录”、原账号“官网登录恢复（保留账号）”、可见预热和后台官网登录维护使用同一官网页面助手。旧 HTTP 登录的可见上下文窗口如果恢复到了官网认证页，也复用此助手；后台获取匿名上下文仍只读，遇到认证即停止。默认新增的旧 HTTP 登录入口保留；此助手不改写 SRP，也不绕过官网登录或商城交换。

## 自动处理的步骤

- 在当前账号任务的官方商城登录页面及官方认证 iframe 中，识别明确的账号、密码输入和对应“继续 / 登录”按钮。
- 核对账号与当前所选账号一致，使用鼠标点击聚焦、键盘全选 / 删除，逐字键入账号与可用密码；每字及鼠标按下到抬起的延迟统一随机为 100–200 ms。远程输入和自动助手复用相同输入工具。按钮使用正常鼠标点击，不直接赋值、不调用 `fill()` / `insert_text()` 或合成 DOM 事件。
- 已填写的账号、密码可以直接继续。密码来自按账号隔离的服务内存、可用凭据保险库或浏览器已填写的当前账号表单；缺少密码时沿用应用密码提示，是否保存服从用户选择。Docker 配置加密文件保险库后，明确选择保存且认证成功的密码可在重启后复用；未配置可用后端时只在本次服务运行中复用。
- 明确的官网“信任此浏览器”步骤沿用已有授权处理；随后仍等待认证与商城交换结束，核验官网实际账号，成功后才保存会话。
- “使用现有凭证登录”只向当前账号任务发送一个操作请求，由持有登录助手的线程继续执行；密码不会传回前端。按钮读取本任务已有密码、系统保险库或当前官网预填密码，缺少可用密码时交回人工。自动输入因导航或焦点变化中断后，用户可明确继续尚未提交的步骤；已提交步骤和未知响应不会重放。

识别同时覆盖商城原生账号字段、唯一可见密码字段和官方认证 iframe；不再要求密码必须具有认证 iframe 的固定 ID 或标签。兼容语义字段和常见字段 ID 只是定位规则，没有把合成表单当作 Apple 现场 DOM 已核实。找不到唯一明确字段或按钮时保留人工处理，不猜测任意页面上的输入用途。非美式键盘字符的底层事件由 Chromium 决定，不能宣称每个 Unicode 字符都有同一组物理按键事件。

## 人工与失败处理

0.1.9 起，维护、购买、首次官网登录和原账号恢复共用自动助手。普通账号、密码和信任步骤自动完成；需要六位验证码时，在当前任务中提示本人输入，再向原浏览器的当前验证表单逐位输入并继续。提示绑定账号、任务及提示 ID，等待验证码不消耗自动操作时限，取消会终止同一任务。不自动获取验证码或切换验证方式；无法识别的挑战报告具体原因。

每个账号和密码步骤在一次助手任务中最多提交一次，即使 iframe 被替换或响应不明也不重交。六位验证码兼容单框和六格输入，输入最后一位后由官网自动提交，不追加点击或回车，避免延迟自动提交时重发。只有官网明确拒绝当前密码才使对应旧凭据失效，验证码错误和普通网络失败不删除密码。保留账号、Cookie、信任和浏览器资料；历史冷却 / 541 标记不否决当前正常恢复，本次 403 / 429 / 541 结束本次尝试，不循环认证。最终核对实际账号后才导入会话。

输入期间逐字检查任务取消、页面 / iframe 导航（包括同 URL 重载）、原字段身份、焦点和当前输入前缀；变化时立即停止剩余输入，避免把密码后半段发送到新页面。诊断只含阶段和公开错误码，不含账号、密码、验证码或原始 Playwright 异常正文。

自动恢复采用有界操作时限（购买前恢复为 120 秒），进入验证码等待后单独计时。后台完整登录统一使用浏览器；自提准备已经进入官网当前 Checkout 后，可以在该认证范围内沿用原 Session 完成结账认证，退出范围即恢复限制，准备仍不提交订单。

## Docker

空闲维护和购买前恢复使用 `--headless=new`，无需 `DISPLAY`；手动官网恢复保留原 Xvfb 和预览入口。六位验证码通过当前应用任务输入，无需改走手动官网登录。容器加密保险库使用独立只读挂载密钥与持久化密文，配置见 [Docker 部署](../docker/README.md)；不复制 Windows 凭据、不存明文密码。没有可用保存密码时仍需输入密码。

## 验证边界

单元回归覆盖字段与账号绑定、每阶段只提交一次、已填写密码、密码读取期间导航、同 URL 重载、字段替换、焦点干预和取消，以及明确继续未提交步骤、没有现有密码、认证拒绝和未知点击不重试。

`scripts/verify-browser-autofill-fixture.py` 验证原有非自动模式和键鼠输入边界；`scripts/verify-browser-automatic-fixture.py` 覆盖当前自动模式的六位验证码、前导零、六格输入、焦点变化、账号页转认证、旧标记和取消。使用真实 Chrome/CDP、隔离临时资料及合成官方表单，拦截页面请求并禁止外部请求；延迟自动提交场景检查一次验证码提交。身份导入使用合成核验，不能据此证明真实 Apple 登录成功、541 已解决或实际下单成功。


## 0.1.6 凭据生命周期

应用密码提示及任务预填统一进入按账号隔离的服务内存缓存。后续查询、下单重新认证、登录恢复与空闲无头官网填写都可复用，不再因上一个 worker 退出就丢失；重试和队列继续使用同一来源。0.1.9 起并发购买子路的在途结账认证由父账号协调提供凭据与验证码，保留原 Checkout；完整浏览器恢复仍在父账号购买前执行。

缓存通过私有 stdin 传给 worker，不进入业务参数、任务文件、摘要或日志；服务重启、删除保存密码和移除账号会清空内存缓存。官网明确拒绝密码会停止对应旧缓存及旧保险库密码的自动复用，等待本人输入；541、验证码和网络问题不当成密码错误。0.1.7 起 Linux / Docker 可配置加密文件保险库，未配置后端时仍只在本次运行内复用。

官网已有密码自动填写仍直接继续该表单，不读取密码 DOM。通过远程官网窗口直接输入的文本不猜测为密码，也不采集到应用缓存；它与浏览器 profile / Cookie 的持久化是两种不同状态。

# 按预选门店和时段自动自提

## 协议依据

Apple 中国大陆[取货说明](https://www.apple.com.cn/shop/help/shipping_delivery)支持在结账时更换零售店，部分商品可选择取货时段；取货联系人仍须满足官网的姓名与证件要求。这里使用现有 Apple Store 网页结账协议，不是 App Store 数字内购 SDK。

现有结账模型包含 `storeLocator.search`、`storeLocator.select` 和 `selectStore`，返回的 `retailStores` 带门店编号与可选状态。选择门店后，官网返回属于该门店的预约日期和时段，提交表单需要当次响应中的签名及完整时段字段。预选列表只能决定从哪些门店中选择、按何顺序选择；不能把库存探针结果当作库存预留，也不能构造官网未返回的时段。

## 使用方式

在“本地配置”的自提偏好中，选择“按预选顺序选择有货门店”，从官网读取多家门店并调整先后顺序。旧的固定单店配置继续可用。

时段规则：

- 最早可用：按官网可用日期及开始时间，从早到晚选择。
- 最晚可用：在官网返回的有效时段中，从晚到早选择。
- 每日时间范围：只选择完整落入设定范围内的时段，再按日期及时间选择最早项。没有匹配时，可选当前优先门店的最早可用时段，或继续尝试下一家预选门店；全部不匹配则停止。

门店顺序优先。没有预约要求的门店可以继续；禁用、受限、不完整、属于其他门店或缺少有效签名的时段不能被选择。只有明确未进入订单提交、官网明确证明当前门店或时段不可用时，才尝试下一家；网络失败和提交未知不会触发盲目换店。

保存门店与时段偏好不再要求先填满联系人。可选择优先使用官网保存的取货联系人；只有当次官网的完整值或明确的掩码提交绑定能证明复用方式时，才使用它们。缺少信息时使用已保存的本地补充项，仍不足则提示补充。程序不会把掩码当作真实姓名/手机号发送，也不会省略官网明确要求的联系人或证件校验。

Review 会对已经提交的邮箱和手机脱敏。程序只在有本次表单已获官网接受的证据时，核对这些脱敏显示的可见字符，不把 Review 掩码写回联系人。处理规则和实际差异见[联系人复核修复记录](PICKUP-CONTACT-FIX.md)。

## 与自动监控联动

“监控预选门店，有货自动下单”先保存当前账号的偏好，再为其商品和数量合并监控目标。已有监控继续运行，不删除其他账号或商品的设置。

同一账号、SKU 和数量的一组候选门店只形成一次购买意图。有多家同时有货时，选择预设顺序中已确认有货的门店进入队列，不为每家候选店重复创建购买任务。真正结账仍会检查允许的门店及当次预约信息；已核实订单或提交未知不能因另一家候选店有货而重放这次购买。

等待中的购买保留原 FIFO 位置及首次授权的门店顺序、时段规则。取消授权或移出预选范围只能缩减等待任务的可选门店，不会暗中扩大权限；已开始执行的购买使用已冻结的配置。全部候选门店确认无货后再次有货，才形成新的补货周期。固定单店旧配置保留原有按门店独立排队的行为。

## 开启监控时读取门店

监控进程继续持有匿名动态代理池。其他门店查询通过受限的本机共享查询通道使用该池，避免第二个进程争夺池所有权。查询只访问公开库存接口，不读取账号 Cookie、不停止监控，也不把库存代理用于结账。

代理池没有可派发连接、Apple 返回挑战或接口超时时，查询仍可能失败并显示具体原因；共享查询修复的是“必须停止监控才能读取门店”的限制，不承诺官网每次查询成功。

## 验证边界

策略、签名校验、候选池去重及联系人复用已通过离线结账模型回归；共享查询已验证同时运行监控和读取官网门店，结果见[验收记录](PICKUP-PREFERENCES-VERIFICATION.md)。真实库存不保证结账库存和时段仍然可用。真实下单与付款不能由模拟订单或只读门店查询证明。
